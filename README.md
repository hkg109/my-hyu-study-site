# HJS STUDY

학년, 학기, 과목별 학습 내용과 족보를 Markdown으로 관리하는 개인 학습 사이트입니다.

## 실행

```bash
npm ci
npm run dev
```

개발 서버는 기본적으로 `http://localhost:3000`에서 실행됩니다.

운영 빌드는 다음 순서로 확인합니다.

```bash
npm run build
npm start
```

## 콘텐츠 구조

- `content/lectures/catalog.json`: 학년, 학기, 과목 이름과 순서
- `content/lectures/<학년 ID>/<학기 ID>/<과목 ID>/lecture-*.md`: 새 강의 노트
- `content/practice/*.md`: 화면의 `족보` 탭에 표시되는 Markdown
- `content/weeks/*.md`: 개편 전에 작성한 기존 노트. 카탈로그의 `legacySource`를 통해 새 과목 구조 안에 표시됩니다.

자세한 작성법은 [콘텐츠 관리 안내](docs/content-guide.md)를 참고하세요.

## 비밀번호 설정

비밀번호는 저장소에 두지 않고 서버 환경변수로 관리합니다. 변수 목록과 설명은 [.env.example](.env.example)에 있습니다.

| 변수 | 용도 |
| --- | --- |
| `AUTH_SECRET` | 족보·관리자 인증 쿠키 서명용 비밀값 (32자 이상) |
| `PRACTICE_PASSWORD_DEFAULT` | `accessKey`가 없는 족보의 기본 비밀번호 |
| `PRACTICE_PASSWORD_<KEY>` | `accessKey`를 지정한 족보의 개별 비밀번호 |
| `ADMIN_PASSWORD` | 로컬 개발 서버의 관리자 모드 비밀번호 (배포에는 필요 없음) |

- **로컬**: `.env.example`을 `.env.local`로 복사해 값을 채운 뒤 `npm run dev`를 다시 시작합니다. `.env.local`은 Git에서 제외됩니다.
- **배포**: Vercel 프로젝트의 환경변수에 등록합니다. 로컬 `.env.local`은 배포에 올라가지 않으므로, 로컬에서 열린다고 배포에서도 열리는 것은 아닙니다.

### 기본·개별 비밀번호 연결

족보 frontmatter에는 비밀이 아닌 참조 이름만 적습니다.

```yaml
accessKey: cse-midterm   # → PRACTICE_PASSWORD_CSE_MIDTERM
```

- `accessKey`가 없는 족보는 `PRACTICE_PASSWORD_DEFAULT`로 열립니다.
- `accessKey`는 소문자 영문·숫자와 하이픈(-)만, 32자 이하로 씁니다. 대문자로 바꾸고 `-`를 `_`로 바꾼 이름이 변수명입니다. `default`는 예약어라 쓸 수 없습니다.
- `accessKey`가 있는데 해당 변수가 없으면 기본 비밀번호로 대체하지 않고 잠긴 상태로 둡니다.
- 한 족보의 비밀번호로는 그 족보만 열립니다. 한 번 입력하면 30일 동안 유지되고, 비밀번호나 `accessKey`를 바꾸면 그 족보에 대한 기존 접속만 다시 잠깁니다. `AUTH_SECRET`을 바꾸면 모든 족보와 관리자 접속이 초기화됩니다.

연결은 파일을 직접 고치거나, 관리자 모드에서 족보를 열고 상단의 **접근 설정**에서 바꿀 수 있습니다. 접근 설정 화면은 현재 방식, `accessKey`, 변수명, 이 개발 서버에서의 설정 여부만 보여 주며 비밀번호 값은 보여 주지 않습니다.

### 새 비밀번호 등록·변경

1. 족보에 `accessKey`를 정합니다 (예: `ds-midterm` → `PRACTICE_PASSWORD_DS_MIDTERM`).
2. 로컬: `.env.local`에 `PRACTICE_PASSWORD_DS_MIDTERM=새 비밀번호`를 추가하고 개발 서버를 다시 시작합니다.
3. 배포: Vercel → 프로젝트 → **Settings → Environment Variables**에서 같은 이름으로 추가합니다. Production과 Preview 중 쓸 환경을 모두 체크합니다.
4. Vercel의 **Deployments**에서 최신 배포를 **Redeploy**합니다. 환경변수는 다시 배포해야 반영됩니다.

비밀번호를 바꿀 때도 같은 변수의 값을 수정한 뒤 다시 배포하면 됩니다. 그 족보를 이미 연 사람은 새 비밀번호를 다시 입력해야 합니다.

새 `accessKey`를 쓰는 족보를 배포할 때는 **환경변수를 먼저 등록하고** 코드를 배포해야 그 사이에 족보가 잠기지 않습니다.

### 환경변수가 없을 때

| 증상 | 원인과 해결 |
| --- | --- |
| 모든 족보가 "지금은 열 수 없는 족보입니다"로 표시됨 | `AUTH_SECRET`이 없거나 32자보다 짧습니다. 값을 등록하고 다시 시작/배포합니다. |
| 특정 족보만 열 수 없음 | 그 족보의 `PRACTICE_PASSWORD_<KEY>`가 없습니다. 관리자 **접근 설정**에서 변수명을 확인해 등록합니다. |
| `accessKey` 없는 족보가 열리지 않음 | `PRACTICE_PASSWORD_DEFAULT`가 없습니다. |
| 관리자 모드를 시작할 수 없음 | 로컬 `.env.local`에 `ADMIN_PASSWORD`와 `AUTH_SECRET`을 설정하고 개발 서버를 다시 시작합니다. |

설정이 빠져도 공개 강의와 목록, 검색은 그대로 동작합니다. 서버 로그에는 빠진 변수 **이름**만 경고로 남습니다.

### 이전 비밀번호 교체

예전에는 비밀번호를 `config/access.json`과 족보 frontmatter에 적었습니다. 지금 파일에서는 지웠지만 **Git 기록에는 남아 있으므로**, 저장소를 본 사람이 알 수 있다고 보고 모든 비밀번호를 새 값으로 바꿔 환경변수에 등록하세요. Git 기록에서 지우려면 이력 재작성(예: `git filter-repo`)과 강제 푸시가 필요해 별도 작업으로 진행합니다. 인증 형식이 바뀌었기 때문에 이 버전을 배포하면 방문자는 각 족보의 비밀번호를 한 번 다시 입력해야 합니다.

## 관리자 모드

관리자 기능은 `npm run dev`로 실행한 로컬 사이트에서만 활성화됩니다. 비밀번호(`ADMIN_PASSWORD`)는 서버에서 확인하고, 인증은 12시간 동안 유지되는 HttpOnly 쿠키로 관리합니다. 관리자 모드를 종료하면 그 쿠키도 무효가 됩니다.

- 학년, 학기, 과목 추가
- 학년명, 학기명, 과목명 수정
- 템플릿으로 새 강의 노트와 족보 만들기
- 강의 제목과 Markdown 본문 수정
- 족보 제목, 설명, Markdown 본문 수정
- 족보 접근 설정(기본 비밀번호 / 개별 비밀번호 키)

관리자 모드에서는 비밀번호 설정과 관계없이 모든 족보를 열어 편집할 수 있습니다. 이 기능은 로컬 개발 서버에서만 동작합니다.

관리자 변경은 프로젝트의 JSON 또는 Markdown 파일에 바로 저장됩니다. 운영 배포에서는 관리자 버튼과 저장 API가 비활성화됩니다.

### 템플릿으로 새 노트·족보 만들기

1. 관리자 모드를 켜고 왼쪽 메뉴(모바일은 메뉴 버튼)에서 과목 옆 `+`를 누릅니다. 강의 정리 화면에서는 강의 노트, 족보 화면에서는 족보가 만들어집니다.
2. 제목을 입력하고 템플릿을 고릅니다. 각 템플릿 아래에 용도와 생성될 구조가 표시되고, **Markdown 미리보기**로 전체 내용을 확인할 수 있습니다.
   - 강의 노트: 빈 노트 · 강의 정리 · 코딩 과제
   - 족보: 빈 노트 · 객관식 족보 · 서술형 족보
3. 족보는 접근 방식(기본 비밀번호 / 개별 비밀번호 키)도 고릅니다.
4. 만들기를 누르면 파일 이름(`lecture-NN.md`, `exam-NN.md`)과 순서가 자동으로 정해지고, 새 문서의 편집기가 열립니다. 기존 파일은 덮어쓰지 않습니다.

템플릿을 고치거나 추가하려면 `lib/note-templates.ts`를 수정합니다.

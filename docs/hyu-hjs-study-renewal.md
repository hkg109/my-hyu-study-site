# HYU hjs-study 사이트 개편 개발 명세

## 1. 개편 목적

현재의 FORIF C++ 스터디 사이트를 개인 과목별 학습 기록 사이트로 개편한다.

- 사이트의 기존 디자인과 Markdown 기반 콘텐츠 관리 방식은 최대한 재사용한다.
- C++ 전용 사이트라는 인상을 제거한다.
- 학습 자료를 `학년 > 학기 > 과목 > 강의` 구조로 탐색할 수 있게 한다.
- 기존 실습 영역은 `족보` 영역으로 변경한다.
- 콘텐츠 본문은 코드 수정 없이 Markdown 파일을 추가하거나 수정해서 관리할 수 있어야 한다.

## 2. 브랜드 및 문구 변경

사이트 전체에서 FORIF 및 C++ 스터디 관련 브랜드와 문구를 제거한다.

| 기존 문구 | 변경 문구 |
| --- | --- |
| `Handsome C++` | `HYU hjs-study` |
| `FORIF STUDY NOTES` | `STUDY NOTES` |
| `미남들과 함께하는 C++` | `HYU STUDY NOTE` |
| `한지석 윤정재` | `한지석` |
| `FORIF / C++ STUDY` | `HYU STUDY` |

추가 변경 범위:

- 헤더 로고와 홈 링크의 접근성 문구
- 브라우저 탭 제목과 SEO metadata
- 홈 화면 소개 문구
- 푸터와 왼쪽 사이드바 하단 문구
- 모바일 메뉴 제목 및 설명
- 검색창, 빈 화면, 소개 페이지 등에 남아 있는 C++·FORIF·주차별 스터디 표현
- README와 콘텐츠 작성 안내 문서
- 패키지 이름 `forif-cpp-study`

완료 후 사용자에게 노출되는 화면과 metadata에 `FORIF`, `Handsome C++`, `C++ STUDY`가 남아 있지 않아야 한다. 기존 학습 자료 본문과 보관용 문서의 C++ 예제는 새 콘텐츠로 교체하기 전까지 개발 범위에서 제외할 수 있지만, 내비게이션과 공통 UI에는 노출하지 않는다.

## 3. 사이트 성격 변경

이 사이트는 더 이상 C++ 스터디 사이트가 아니다. 한양대학교 과목별 학습 내용을 정리하는 개인 학습 노트로 사용한다.

- 특정 프로그래밍 언어를 전제로 한 소개 문구를 사용하지 않는다.
- 코드 블록, 목차, 검색, 학습 완료 표시, 이전·다음 이동, 인쇄/PDF 기능 등 범용 학습 기능은 유지한다.
- 과목에 따라 텍스트, 수식, 코드, 이미지, 링크를 자유롭게 Markdown 안에 작성할 수 있어야 한다.

## 4. 상단 탭 구성

상단의 주요 탭은 다음 두 개만 표시한다.

1. `강의 정리`
2. `족보`

기존 `강의노트` 표기는 `강의 정리`로 변경한다. 기존 `실습` 탭과 화면은 `족보`로 변경한다. 과제 및 소개 메뉴가 현재 별도 페이지로 존재하더라도 상단 주요 탭에서는 제거한다.

### 4.1 강의 정리

기존의 `Week > Lecture` 구조를 다음 구조로 교체한다.

```text
학년
└─ 학기
   └─ 과목
      ├─ Lecture 01
      ├─ Lecture 02
      └─ Lecture 03
```

예시:

```text
2학년
└─ 1학기
   ├─ 자료구조
   │  ├─ Lecture 01 — 시간 복잡도
   │  └─ Lecture 02 — 연결 리스트
   └─ 선형대수
      └─ Lecture 01 — 벡터와 행렬
```

요구사항:

- 학년은 숫자 오름차순으로 정렬한다.
- 같은 학년 안에서 학기는 숫자 오름차순으로 정렬한다.
- 같은 학기 안에서 과목 순서를 지정할 수 있어야 한다.
- 같은 과목 안에서 강의 순서를 지정할 수 있어야 한다.
- 한 과목에 강의 Markdown 파일을 계속 추가할 수 있어야 한다.
- 목록, 검색 결과, breadcrumb, 이전·다음 이동에 학년·학기·과목 정보가 반영되어야 한다.
- 기존 `WEEK 01` 같은 표시는 학년·학기·과목 또는 `LECTURE 01` 정보로 교체한다.

권장 콘텐츠 구조:

```text
content/
└─ lectures/
   └─ grade-02/
      └─ semester-01/
         └─ data-structures/
            ├─ lecture-01.md
            ├─ lecture-02.md
            └─ lecture-03.md
```

권장 frontmatter 예시:

```yaml
---
title: 시간 복잡도
description: 알고리즘의 수행 시간을 표현하는 방법을 정리합니다.
grade: 2
semester: 1
subject: 자료구조
subjectSlug: data-structures
subjectOrder: 1
lecture: 1
published: true
---
```

URL 예시:

```text
/lectures/grade-02/semester-01/data-structures/lecture-01
```

### 4.2 관리자 모드의 분류 관리

관리자 모드에서는 개발자가 코드를 수정하지 않아도 강의 정리의 전체 분류를 화면에서 관리할 수 있어야 한다.

- `학년 추가` 버튼으로 새 학년을 추가할 수 있다.
- 각 학년 안의 `학기 추가` 버튼으로 새 학기를 추가할 수 있다.
- 각 학기 안의 `과목 추가` 버튼으로 새 과목을 추가할 수 있다.
- 학년명, 학기명, 과목명을 관리자 모드에서 모두 수정할 수 있다.
- 이름 수정은 인라인 입력 또는 편집 대화상자로 제공하며, 저장과 취소 동작을 명확히 구분한다.
- 수정 결과는 새로고침하거나 서버를 다시 실행해도 유지되도록 프로젝트 파일에 저장한다.
- 일반 사용자 모드에서는 추가·수정 버튼과 입력창이 보이지 않는다.
- 빈 이름, 같은 상위 분류 안의 중복 이름, 사용할 수 없는 slug는 저장하지 않고 오류를 안내한다.
- 표시 이름을 수정하더라도 기존 Markdown 파일과 링크가 깨지지 않도록 내부 식별자와 URL slug는 표시 이름과 분리한다.

권장 분류 데이터 예시:

```json
{
  "grades": [
    {
      "id": "grade-02",
      "name": "2학년",
      "order": 2,
      "semesters": [
        {
          "id": "semester-01",
          "name": "1학기",
          "order": 1,
          "subjects": [
            {
              "id": "data-structures",
              "name": "자료구조",
              "order": 1
            }
          ]
        }
      ]
    }
  ]
}
```

분류 정보는 예를 들어 `content/lectures/catalog.json`에 저장하고, Markdown 파일은 해당 분류의 안정적인 `id`를 참조한다. 실제 구현 시에도 표시 이름 변경 때문에 디렉터리나 기존 URL을 강제로 변경하지 않는 구조를 우선한다.

### 4.3 관리자 모드의 노트 추가

각 과목 영역에 관리자 모드에서만 보이는 `+` 버튼을 제공한다. 이 버튼으로 선택한 과목에 새 강의 노트를 추가할 수 있어야 한다.

노트 추가 흐름:

1. 관리자가 원하는 과목의 `+` 버튼을 누른다.
2. 새 노트의 제목을 입력한다.
3. 시스템이 해당 과목의 다음 강의 순서를 자동으로 제안한다.
4. 저장하면 프로젝트의 해당 과목 경로에 Markdown 파일을 생성한다.
5. 생성 직후 새 노트 편집 화면으로 이동해 본문을 작성할 수 있게 한다.

추가 요구사항:

- 필요하면 생성 전에 강의 순서를 직접 수정할 수 있다.
- 파일명과 slug는 제목이 아니라 충돌하지 않는 안정적인 값으로 생성한다.
- 같은 과목 안에서 slug 또는 강의 순서가 중복되지 않게 검증한다.
- 새 Markdown 파일에는 학년·학기·과목·제목·순서·공개 여부 등 필수 frontmatter를 자동으로 작성한다.
- 최초 본문에는 바로 수정할 수 있는 최소 템플릿을 넣는다.
- 파일 생성 실패 시 목록에 잘못된 항목을 남기지 않고 원인을 안내한다.
- 운영 배포 환경에서는 기존 관리자 정책에 따라 파일 생성 API를 비활성화하고, 로컬 개발 환경의 관리자 모드에서만 파일을 생성한다.

생성되는 Markdown 예시:

```md
---
title: 새 강의 노트
gradeId: grade-02
semesterId: semester-01
subjectId: data-structures
lecture: 3
published: true
---

# 새 강의 노트

여기에 학습 내용을 작성하세요.
```

## 5. 족보

기존 실습 영역의 UI와 기능을 재사용하되, 사용자에게는 모두 `족보`로 표시한다.

유지할 기능:

- Markdown/MDX 렌더링
- 제목, 설명 및 본문 표시
- 페이지 내 목차
- 검색
- 관리자 모드에서 Markdown 내용 편집 및 저장
- 반응형 레이아웃
- 라이트·다크 테마
- 기존에 제공되는 코드 블록, 콜아웃, 답안 등의 Markdown 컴포넌트

변경할 내용:

- `실습`, `Practice` 표기를 `족보`로 변경한다.
- 기존 실습 샘플 내용은 실제 족보 Markdown 내용으로 교체할 수 있게 한다.
- 족보 본문은 소스 컴포넌트를 수정하지 않고 Markdown 파일만 수정해서 관리할 수 있어야 한다.
- 주차 전용 표현이 화면에 노출되지 않도록 한다.

초기 개편에서는 기존 `/practice` 경로와 `content/practice` 내부 구조를 유지해 기능 변경 위험을 줄일 수 있다. 다만 사용자에게 보이는 모든 링크와 문구는 `족보`여야 한다. 추후 필요하면 내부 경로를 `/exams`와 `content/exams`로 일괄 이전한다.

## 6. 왼쪽 사이드바 접기/펼치기

데스크톱 화면에서 왼쪽 탐색 사이드바 전체를 접거나 다시 펼칠 수 있게 한다.

- 사이드바 상단 또는 경계에 접기/펼치기 버튼을 둔다.
- 접힌 상태에서는 본문 영역이 남은 너비를 사용한다.
- 접힌 상태에서도 사용자가 기능을 알아볼 수 있는 아이콘 또는 펼치기 버튼을 남긴다.
- 버튼에 `aria-label`, `aria-expanded`, 키보드 포커스 스타일을 제공한다.
- 새로고침 후에도 상태가 유지되도록 브라우저의 `localStorage`에 저장한다.
- 모바일에서는 기존 드로어 메뉴 방식을 유지한다.
- 학년·학기·과목 그룹 자체도 각각 접고 펼칠 수 있게 한다.

## 7. 유지해야 할 공통 기능

사이트 구조를 변경하더라도 다음 기능은 유지한다.

- 전체 콘텐츠 검색
- Markdown 및 MDX 렌더링
- 오른쪽 페이지 목차
- 강의 학습 완료 체크와 이어서 학습하기
- 이전·다음 강의 이동
- 강의 인쇄/PDF 저장
- 라이트·다크 테마
- 모바일 내비게이션
- 로컬 관리자 편집 모드
- 정적 빌드 및 Vercel 배포

기존 진행 상태가 `week-*` 키에 의존하므로 새 강의 경로 체계에 맞는 진행 상태 키로 변경해야 한다. 가능하면 기존 브라우저 데이터가 오류를 일으키지 않도록 안전하게 무시하거나 마이그레이션한다.

- `components/layout/Footer.tsx`: HYU 브랜드와 작성자 변경
- `components/layout/PageTOC.tsx`: C++ 관련 문구 제거
- `components/lecture/**`: WEEK 중심 breadcrumb, 라벨 및 이동 UI 변경
- `components/ui/SearchDialog.tsx`: 새 계층 metadata와 족보 명칭 반영
- `lib/content.ts`, `lib/lectures.ts`, `lib/weeks.ts`: 새 콘텐츠 스키마와 정렬 규칙 구현

- `content/**`: 새 디렉터리 구조와 예시 Markdown 준비
- `docs/content-guide.md`, `README.md`: 새 콘텐츠 작성법 반영

## PART 1 · 리눅스 개요

## 1. 리눅스란 무엇인가

### 핵심 필기

> [!CONCEPT]
> **리눅스(Linux)** — 1991년 ==리누스 토르발스(Linus Torvalds)가 처음 공개한 유닉스 호환 운영체제 커널==, 그리고 이 커널에 GNU 도구·라이브러리·응용 프로그램을 묶어 만든 운영체제 전체를 가리킨다. 엄밀히 말해 "리눅스"는 커널의 이름이고, 운영체제 전체는 ==GNU/Linux==라고도 부른다.

리눅스 시스템은 네 겹으로 생각하면 쉽다.

| 구성 요소 | 하는 일 | 예 |
| --- | --- | --- |
| **하드웨어** | 실제 장치 | CPU, 메모리, 디스크, 네트워크 카드 |
| **커널(Kernel)** | 하드웨어를 직접 제어하고 자원을 나눠 주는 운영체제의 핵심 | 프로세스·메모리·파일 시스템·장치·네트워크 관리 |
| **셸(Shell)** | ==사용자의 명령을 해석해 커널에 전달하는 명령어 해석기== | bash, sh, csh, tcsh, ksh, zsh |
| **응용 프로그램·유틸리티** | 사용자가 실제로 쓰는 프로그램 | ls, vi, gcc, 웹 브라우저, 오피스 |

여기에 모든 자료를 `/`(루트)에서 뻗어 나가는 계층형 디렉터리 구조로 관리하는 **파일 시스템**을 더해 "커널·셸·파일 시스템"을 리눅스의 3대 구성 요소로 꼽기도 한다.

[![하드웨어를 맨 아래에 두고 커널, 시스템 호출, 셸, 응용 프로그램, 사용자가 차례로 쌓인 층 구조와, 사용자 명령이 셸에서 해석되어 커널을 거쳐 하드웨어에 닿는 흐름, 커널의 다섯 가지 관리 기능을 정리한 그림](/materials/diagrams/lm2-l01a-layers.svg)](/materials/diagrams/lm2-l01a-layers.svg)

*그림 1-1 · 리눅스 시스템의 층 구조 — 누르면 원본 크기로 열린다.*

> [!NOTE]
> - **읽는 순서:** 맨 위 사용자 → 셸(명령 해석) → 시스템 호출 → 검은 커널 → 하드웨어. 오른쪽 상자는 커널이 맡는 다섯 가지 관리 기능이다.
> - **핵심:** 사용자는 하드웨어를 직접 만지지 않는다. ==셸은 통역사, 커널은 관리자==이고 둘 사이를 시스템 호출이 잇는다.
> - **시험 포인트:** ==red:"명령어를 해석해 커널에 전달" = 셸, "하드웨어·자원 관리" = 커널==. 보기에서 두 설명을 바꿔 넣는다.

### 커널이 하는 일

==blue:프로세스 관리 · 메모리 관리 · 파일 시스템 관리 · 디바이스(장치) 관리 · 네트워크 관리== ("프메파디네")

| 기능 | 내용 |
| --- | --- |
| 프로세스 관리 | 프로세스 생성·종료, CPU 스케줄링, 프로세스 간 통신(IPC) |
| 메모리 관리 | 가상 메모리, 페이징, 스왑(디스크 일부를 메모리처럼 사용) |
| 파일 시스템 관리 | VFS(가상 파일 시스템)로 ext4·xfs·vfat 등 여러 형식을 같은 방식으로 접근 |
| 디바이스 관리 | 장치 드라이버로 하드웨어 제어, 장치를 `/dev` 아래 파일로 표현 |
| 네트워크 관리 | TCP/IP 프로토콜 스택, 네트워크 인터페이스 제어 |

**커널 구조 비교**

| 구분 | 모놀리식 커널(Monolithic) | 마이크로커널(Microkernel) |
| --- | --- | --- |
| 구조 | 핵심 기능 대부분이 커널 공간 한 덩어리 | 최소 기능만 커널에, 나머지는 사용자 공간 서버 |
| 장점 | 빠르다 (기능 간 호출이 직접적) | 안정성·확장성 (한 서버가 죽어도 전체는 유지) |
| 예 | ==리눅스==, 전통적 유닉스 | Minix, Mach, GNU Hurd, QNX |

> [!TRAP]
> ==red:리눅스는 모놀리식 커널이지만 "모듈"을 지원한다.== 장치 드라이버 같은 기능을 **커널 모듈(LKM, Loadable Kernel Module)** 로 만들어 재부팅 없이 올리고 내릴 수 있다(`lsmod`, `modprobe`, `insmod`, `rmmod` — 10편). "리눅스는 마이크로커널이다"는 오답.

### 셸이 하는 일

- 사용자가 입력한 명령을 ==해석(interpret)해 커널에 전달==하는 **명령어 해석기**이자 사용자 인터페이스.
- 변수·조건문·반복문을 가진 **프로그래밍 언어**이기도 해서 셸 스크립트를 만든다.
- 종류: ==blue:sh(Bourne) · csh · ksh · tcsh · bash · zsh== — 대부분의 배포판 기본은 **bash**(Bourne Again Shell). 자세한 내용은 6편.

```bash
$ echo $SHELL          # 로그인 셸
/bin/bash
$ cat /etc/shells      # 로그인 셸로 쓸 수 있는 셸 목록 (Ubuntu 예, 일부)
# /etc/shells: valid login shells
/bin/sh
/bin/bash
/usr/bin/bash
/usr/bin/dash
```

## 2. 리눅스의 특징과 장단점

### 핵심 필기

| 특징 | 뜻 |
| --- | --- |
| **멀티유저(다중 사용자)** | 여러 사용자가 동시에 접속해 각자의 계정·권한으로 작업 |
| **멀티태스킹(다중 작업)** | 여러 프로세스를 동시에(번갈아) 실행 |
| **다중 스레드·SMP 지원** | 여러 CPU(코어)를 함께 사용 |
| **이식성(Portability)** | 커널 대부분이 ==C 언어로 작성==되어 x86, ARM, RISC-V 등 여러 아키텍처로 옮기기 쉬움 |
| **계층적 파일 시스템** | `/`를 꼭대기로 하는 트리 구조, 장치도 파일로 다룸 |
| **가상 메모리·스왑** | 물리 메모리가 부족하면 디스크의 스왑 영역 사용 |
| **다양한 파일 시스템 지원** | ext2/3/4, xfs, btrfs, vfat, NTFS, iso9660 등 |
| **강력한 네트워크** | TCP/IP를 기본 지원, 서버 운영체제로 널리 사용 |
| **POSIX 호환** | 유닉스 표준 인터페이스를 따라 유닉스용 프로그램을 쉽게 옮김 |
| **가상 콘솔** | 한 화면에서 `Ctrl+Alt+F1`–`F6` 등으로 여러 터미널 전환 |
| **공유 라이브러리** | 여러 프로그램이 같은 라이브러리(`.so`)를 함께 사용해 메모리 절약 |
| **자유 소프트웨어·오픈소스** | 소스 코드가 공개되어 누구나 연구·수정·재배포 가능 |

| 장점 | 단점 |
| --- | --- |
| 무료로 구해 쓸 수 있고 소스가 공개되어 있다 | 공식 기술 지원이 상용 OS보다 약하다 (상용 배포판은 유료 지원 계약) |
| 안정적이고 보안 패치가 빠르다 | 일부 하드웨어 드라이버·상용 프로그램 지원이 늦거나 부족하다 |
| 적은 자원으로도 동작하고 서버·임베디드로 확장된다 | 배포판이 많아 설정 방식이 제각각이다 |
| 커뮤니티가 크고 문서가 풍부하다 | 소스가 공개되어 있어 취약점이 알려지기 쉽다 |

> [!TRAP]
> ==red:"리눅스는 단일 사용자·단일 작업 운영체제다", "어셈블리어로 작성되어 이식성이 낮다"는 오답이다.== 또 "오픈소스이므로 아무 조건 없이 소스를 비공개로 재배포할 수 있다"도 틀렸다 — 커널은 GPL이라 수정해 배포하면 소스를 공개해야 한다.

> [!EXAMPLE]
> **지금 쓰는 리눅스의 커널 버전 확인하기**
>
> ```bash
> $ uname -r
> 6.18.44-fc-v185
> $ uname -a
> Linux vm 6.18.44-fc-v185 #1 SMP PREEMPT_DYNAMIC @0 x86_64 x86_64 x86_64 GNU/Linux
> $ cat /proc/version
> Linux version 6.18.44-fc-v185 (builder@sandboxing) (gcc (GCC) 15.3.0, GNU ld (GNU Binutils) 2.46) #1 SMP ...
> ```
>
> `uname -a`의 `SMP`는 다중 프로세서 지원, 끝의 `GNU/Linux`는 운영체제 이름이다. 배포판 정보는 `cat /etc/os-release`로 본다.

## PART 2 · 리눅스의 역사

## 3. 유닉스에서 리눅스까지

### 핵심 필기

| 연도 | 사건 | 인물·단체 |
| --- | --- | --- |
| 1965 | MULTICS 프로젝트 (MIT·GE·벨 연구소) — 너무 복잡해 벨 연구소가 1969년 탈퇴 | — |
| **1969** | ==AT&T 벨 연구소에서 유닉스(UNIX) 개발== (처음엔 어셈블리어) | 켄 톰슨(Ken Thompson), 데니스 리치(Dennis Ritchie) |
| **1973** | ==유닉스를 C 언어로 다시 작성== → 이식성 확보 | 데니스 리치 (C 언어 개발자) |
| 1977년 이후 | 버클리 대학의 BSD 유닉스 → FreeBSD·NetBSD·OpenBSD, macOS의 뿌리 | UC 버클리 |
| 1980년대 | 유닉스 상용화·분열 — AT&T System V 계열 vs BSD 계열 | — |
| **1983** | ==GNU 프로젝트 시작== (완전히 자유로운 유닉스 호환 OS 목표) | 리처드 스톨먼(Richard Stallman) |
| **1985** | ==FSF(자유 소프트웨어 재단) 설립==, GNU 선언문 발표 | 리처드 스톨먼 |
| 1987 | 교육용 유닉스 호환 OS **Minix** 발표 (마이크로커널) | 앤드루 타넨바움(Andrew Tanenbaum) |
| 1989 | **GPL v1** 발표 (1991년 GPLv2, 2007년 GPLv3) | FSF |
| **1991** | ==리눅스 커널 0.01 공개== (8월 comp.os.minix에 개발 소식, 9월 0.01, 10월 0.02) | 리누스 토르발스 (핀란드 헬싱키 대학생) |
| 1992 | 커널을 GPL로 배포하기 시작 → GNU 도구와 결합한 완전한 OS | — |
| **1994** | 리눅스 커널 1.0 발표 | — |
| 1996 | 2.0 (SMP 지원), 펭귄 마스코트 **턱스(Tux)** 등장 | — |
| 1998 | ==OSI(Open Source Initiative) 설립==, "오픈소스"라는 용어 등장 | 에릭 레이먼드, 브루스 페런스 |
| 2011 | 3.0 (리눅스 20주년) — 이후 4.0(2015), 5.0(2019), 6.0(2022) | — |

> [!CONCEPT]
> **GNU** = "==GNU's Not Unix==" — 이름 안에 자기 이름이 다시 들어가는 **재귀 약어**다. GNU 프로젝트는 컴파일러(**GCC**), C 라이브러리(**glibc**), 셸(**bash**), 편집기(**Emacs**) 등을 만들었지만 커널(GNU Hurd)이 늦어졌다. 그 빈자리를 리눅스 커널이 채워 오늘의 GNU/Linux가 되었다.

> [!TRAP]
> ==red:리누스 토르발스는 "커널"을 만들었고, GNU 프로젝트·FSF·GPL은 리처드 스톨먼이다.== 유닉스는 켄 톰슨·데니스 리치, Minix는 앤드루 타넨바움. 인물과 업적을 섞어 내는 문제가 자주 나온다. 리눅스는 Minix의 영향을 받았지만 ==Minix의 소스를 이어받은 것이 아니라 새로 작성==했다.

> [!NOTE]
> 1991년 8월 리누스가 뉴스그룹에 올린 글은 "그냥 취미로 하는 작은 운영체제(just a hobby, won't be big and professional like gnu)"라는 문장으로 유명하다. 처음에는 Minix 위에서 개발했고, 인텔 386 PC에서만 돌아갔다. 이식성은 이후 C 코드와 전 세계 개발자의 참여로 얻은 것이다.

## 4. 커널 버전 표기

### 핵심 필기

- 현재 형식: ==주 번호.부 번호.패치 번호== — 예 `6.8.12`. 배포판은 뒤에 자체 빌드 번호를 붙인다 (예 `5.14.0-427.el9.x86_64`, `6.8.0-45-generic`).
- 옛 방식(2.6 이전): ==부 번호가 짝수면 안정 버전, 홀수면 개발 버전== (2.4 안정 / 2.5 개발 / 2.6 안정). 2.6 이후로는 이 규칙을 쓰지 않는다.
- 공식 배포처: **kernel.org** — 분류는 mainline(최신 개발), stable(안정), longterm(LTS, 장기 지원).
- 확인 명령: `uname -r`(커널 릴리스), `uname -a`(전체), `cat /proc/version`.

> [!TRAP]
> `uname -r`은 ==red:커널 버전이지 배포판 버전이 아니다.== Rocky Linux 9인지 Ubuntu 24.04인지는 `/etc/os-release`(또는 `/etc/redhat-release`)로 확인한다.

## PART 3 · 리눅스의 핵심 철학 — 오픈소스와 라이선스

## 5. 자유 소프트웨어와 오픈소스

### 핵심 필기

**자유 소프트웨어(Free Software)** — FSF가 말하는 "free"는 ==가격이 공짜(free beer)가 아니라 자유(free speech)==다. 네 가지 자유(0번부터 센다):

| 번호 | 자유 |
| --- | --- |
| 자유 0 | 어떤 목적으로든 프로그램을 **실행**할 자유 |
| 자유 1 | 프로그램이 어떻게 동작하는지 **연구하고 수정**할 자유 (소스 코드 접근이 전제) |
| 자유 2 | 이웃을 돕기 위해 **복사본을 재배포**할 자유 |
| 자유 3 | 개선한 버전을 **배포**해 공동체 전체가 혜택을 보게 할 자유 |

> [!CONCEPT]
> **카피레프트(Copyleft)** — 저작권(copyright)을 이용해 오히려 ==자유를 강제==하는 방식. 프로그램을 수정·재배포할 때 **같은 자유(같은 라이선스)를 그대로 유지**하도록 요구한다. GPL이 대표적이다.

**오픈소스(Open Source)** — 1998년 OSI가 만든 용어. 소스 공개라는 실용적 측면을 강조한다. **오픈소스 정의(OSD)** 의 주요 조건:

1. 자유로운 재배포 (판매·배포를 막지 않음, 로열티 요구 금지)
2. 소스 코드 공개 (또는 쉽게 얻을 수 있는 방법 제공)
3. 2차적 저작물(수정본) 허용
4. 원저작자 소스 코드의 무결성 (수정본은 이름·버전을 달리하도록 요구 가능)
5. 개인·단체에 대한 차별 금지
6. 사용 분야에 대한 차별 금지 (상업적 이용 금지 불가)
7. 라이선스의 배포 (재배포받은 사람에게도 같은 권리)
8. 특정 제품에 종속되지 않음
9. 다른 소프트웨어를 제한하지 않음
10. 기술 중립성

> [!TRAP]
> ==red:"상업적 이용을 금지한다", "특정 분야(예: 군사)에서는 사용할 수 없다"는 오픈소스 정의에 맞지 않는다.== 오픈소스라도 판매할 수 있고, 라이선스 조건(저작권 표시·소스 공개 등)은 지켜야 한다. "오픈소스 = 저작권 없음"도 오답이다.

## 6. 오픈소스 라이선스 비교

### 핵심 필기

| 라이선스 | 소스 공개 의무 | 다른 코드와 결합 시 | 핵심 특징 | 대표 사용처 |
| --- | :---: | --- | --- | --- |
| **GPL** (GNU General Public License) | ==O== | 결합·링크한 프로그램 전체를 GPL로 공개해야 함 | 가장 강한 카피레프트. v2(1991), v3(2007, 특허·티보이제이션 조항) | ==리눅스 커널(GPLv2)==, GCC, bash |
| **LGPL** (Lesser/Library GPL) | O (라이브러리 수정 시) | 라이브러리를 ==동적 링크만 해서 쓰는 프로그램은 공개 의무 없음== | 라이브러리용 약한 카피레프트 | glibc, GTK |
| **MPL** (Mozilla Public License) | O (수정한 파일만) | ==파일 단위==로 적용 — MPL 파일을 고치면 그 파일만 공개, 새로 만든 파일은 비공개 가능 | GPL과 BSD의 중간, 특허 조항 포함 | Firefox, Thunderbird |
| **BSD** | X | 비공개·상용 결합 자유 | 저작권 표시와 면책 조항만 유지하면 됨 | FreeBSD, OpenBSD |
| **Apache 2.0** | X | 비공개·상용 결합 자유 | ==특허권 사용 허락을 명시==, 변경 사항 고지·NOTICE 파일 유지 | Apache HTTP Server, Android(일부), Hadoop |
| **MIT** | X | 비공개·상용 결합 자유 | 가장 짧고 허용적인 라이선스, 저작권 표시만 | X Window(X11), jQuery, Node.js |

*그림 1-2 · 라이선스별 소스 공개 범위 — 누르면 원본 크기로 열린다.*

> [!NOTE]
> - **읽는 순서:** 맨 위 GPL(가장 강한 카피레프트)에서 맨 아래 MIT(가장 허용적)로 내려간다. 각 라이선스 오른쪽 상자에 "무엇을 공개해야 하나"를 적었다.
> - **핵심:** 공개 범위가 ==프로그램 전체(GPL) → 라이브러리 자체(LGPL) → 수정한 파일(MPL) → 없음(Apache·BSD·MIT)== 순으로 좁아진다.
> - **시험 포인트:** ==red:"소스 공개 의무가 없는 것" = BSD·Apache·MIT==, "파일 단위" = MPL, "특허 명시" = Apache(그리고 MPL, GPLv3).

> [!TRAP]
> ==red:LGPL의 L은 "Lesser"(예전 이름 Library)다. 라이브러리를 고치면 그 수정 부분은 공개해야 한다.== "LGPL은 소스 공개 의무가 전혀 없다"는 오답이다. 공개 의무가 없는 것은 그 라이브러리를 **가져다 쓰기만 하는(동적 링크) 프로그램** 쪽이다.

> [!EXAMPLE]
> **상황별로 라이선스 고르기 (학습용 예시)**
>
> | 상황 | 해당 라이선스 |
> | --- | --- |
> | 커널 소스를 고쳐 공유기 제품에 넣어 팔았다 → 고친 커널 소스를 공개해야 한다 | GPL |
> | 회사 앱이 공개 라이브러리를 동적 링크로만 쓴다 → 앱 소스는 공개하지 않아도 된다 | LGPL |
> | 오픈소스 브라우저의 파일 3개를 고치고 새 파일 10개를 추가했다 → 고친 3개만 공개 | MPL |
> | 가져다 쓴 코드의 저작권 문구만 남기고 상용 제품을 비공개로 만들었다 | BSD·MIT |
> | 사용 허락에 특허 사용권까지 명시적으로 포함되어 있다 | Apache 2.0 |

## 7. 배포판의 개념과 3대 계열

### 핵심 필기

> [!CONCEPT]
> **배포판(Distribution)** — 리눅스 커널에 ==GNU 도구, 라이브러리, 설치 프로그램, 패키지 관리자, 응용 프로그램을 묶어 설치·사용하기 쉽게 만든 꾸러미==. 같은 커널이라도 패키지 형식과 관리 도구가 계열마다 다르다.

| 계열 | 패키지 형식 | 저수준 도구 | 고수준(의존성 해결) 도구 | 대표 배포판 |
| --- | --- | --- | --- | --- |
| **Red Hat** | `.rpm` | ==rpm== | yum, dnf | RHEL, Fedora, CentOS(→ CentOS Stream), Rocky Linux, AlmaLinux, Oracle Linux |
| **Debian** | `.deb` | ==dpkg== | apt, apt-get, aptitude | Debian, Ubuntu, Linux Mint, Kali Linux, Raspberry Pi OS |
| **Slackware** | `.tgz`·`.txz` | pkgtool, installpkg | slackpkg | Slackware (현존하는 가장 오래된 배포판, 1993) |
| (SUSE) | `.rpm` | rpm | zypper, YaST | SUSE Linux Enterprise, openSUSE |
| (기타) | — | — | pacman / Portage / apk | Arch Linux / Gentoo(소스 컴파일) / Alpine |

[![Red Hat, Debian, Slackware 세 뿌리에서 갈라진 배포판 가계도. Red Hat에서 RHEL, Fedora, CentOS, Rocky, Alma가, Debian에서 Ubuntu, Mint, Kali가, Slackware에서 SUSE 계열이 갈라지며 각 계열 아래에 패키지 형식과 도구를 적은 그림](/materials/diagrams/lm2-l01c-distros.svg)](/materials/diagrams/lm2-l01c-distros.svg)

*그림 1-3 · 배포판 3대 계열 — 누르면 원본 크기로 열린다.*

> [!NOTE]
> - **읽는 순서:** 맨 위 리눅스 커널 → 세 뿌리(Red Hat·Debian·Slackware) → 각 뿌리 아래 파생 배포판 → 맨 아래 패키지 형식·도구 띠.
> - **핵심:** 배포판 이름을 보면 ==계열 → 패키지 형식 → 도구==가 줄줄이 따라 나온다. Ubuntu면 deb·dpkg·apt, Rocky면 rpm·rpm·dnf.
> - **시험 포인트:** ==red:SUSE는 Slackware에서 출발했지만 지금은 RPM 패키지를 쓴다.== "Debian 계열이 아닌 것"에 Fedora·CentOS를 섞어 낸다.

> **C.** BSD·Apache 2.0(그리고 MIT)은 저작권 표시 등만 지키면 수정본을 비공개로 배포할 수 있다. GPL·LGPL·MPL은 각자의 범위에서 소스 공개 의무가 있다.

> 다음 중 배포판과 기본 패키지 관리 도구의 연결이 옳지 않은 것은?
>
> **A.** Ubuntu — apt
>
> **B.** Rocky Linux — dnf
>
> **C.** Linux Mint — yum
>
> **D.** openSUSE — zypper

> [!HINT 1]
> Linux Mint는 Ubuntu를 바탕으로 만들었다.

> [!ANSWER]
> **C.** Linux Mint는 Debian(Ubuntu) 계열이라 dpkg·apt를 쓴다. yum은 Red Hat 계열 도구다.

> [!QUIZ]
> 다음 중 인물과 업적의 연결이 옳은 것은?

> **A.** 리처드 스톨먼 — 리눅스 커널 0.01 공개
>
> **B.** 리누스 토르발스 — GNU 프로젝트 시작
>
> **C.** 앤드루 타넨바움 — Minix 개발
>
> **D.** 켄 톰슨 — 자유 소프트웨어 재단(FSF) 설립

> [!HINT 1]

> [!ANSWER]
> **C.** 스톨먼은 GNU 프로젝트·FSF·GPL, 토르발스는 리눅스 커널, 켄 톰슨은 데니스 리치와 함께 유닉스를 만들었다.

## 책을 덮고 꺼내 보기

- 사용자의 명령을 해석해 커널에 전달하는 프로그램은 {{셸}}이다.
- 리눅스 커널은 {{모놀리식}} 커널이며 {{모듈}}로 기능을 동적으로 추가한다.
- 유닉스는 1969년 {{AT&T 벨 연구소}}에서 켄 톰슨과 데니스 리치가 만들었다.
- GNU 프로젝트는 1983년 {{리처드 스톨먼}}이 시작했고, GNU는 {{GNU's Not Unix}}의 재귀 약어다.
- 리눅스 커널은 {{GPLv2}} 라이선스로 배포된다.
- 파일 단위로 소스 공개 의무를 지우는 라이선스는 {{MPL}}이다.
- 특허권 사용 허락을 명시한 허용형 라이선스는 {{Apache 2.0}}이다.
- Ubuntu는 {{Debian}} 계열이고 저수준 패키지 도구는 {{dpkg}}다.

> [!FLASHCARD]
> Q: 커널과 셸의 역할 차이는?
> A: 커널은 하드웨어를 직접 제어하고 프로세스·메모리·파일 시스템·장치·네트워크를 관리하는 운영체제의 핵심이다. 셸은 사용자의 명령을 해석해 커널에 전달하는 명령어 해석기이자 스크립트 언어다.

> [!FLASHCARD]
> Q: 리눅스의 주요 특징 다섯 가지는?
> A: 멀티유저, 멀티태스킹, 이식성(C 언어), 계층적 파일 시스템, 가상 메모리(스왑). 그 밖에 POSIX 호환, 강력한 네트워크, 다양한 파일 시스템 지원, 오픈소스.

> [!FLASHCARD]
> Q: 유닉스·GNU·리눅스의 시작 연도와 인물은?
> A: 유닉스 1969년 켄 톰슨·데니스 리치(AT&T 벨 연구소), GNU 1983년 리처드 스톨먼, 리눅스 커널 1991년 리누스 토르발스.

> [!FLASHCARD]
> Q: 자유 소프트웨어의 네 가지 자유는?
> A: 0 실행의 자유, 1 연구·수정의 자유, 2 재배포의 자유, 3 개선한 버전을 배포할 자유.

> [!FLASHCARD]
> Q: GPL과 LGPL의 차이는?
> A: GPL은 GPL 코드와 결합·링크한 프로그램 전체를 GPL로 공개해야 한다. LGPL은 라이브러리 자체를 수정한 부분만 공개하면 되고, 동적 링크로 사용만 하는 프로그램은 공개 의무가 없다.

> [!FLASHCARD]
> Q: 소스 공개 의무가 없는 라이선스 세 가지와 각각의 특징은?
> A: BSD(저작권 표시·면책 조항 유지), Apache 2.0(특허 사용권 명시, NOTICE 유지), MIT(가장 짧고 허용적).

> [!FLASHCARD]
> Q: 배포판 3대 계열의 패키지 형식과 도구는?
> A: Red Hat 계열 — rpm, yum·dnf. Debian 계열 — deb, dpkg·apt. Slackware 계열 — tgz/txz, pkgtool·installpkg.

> [!FLASHCARD]
> Q: 옛 커널 버전 규칙에서 짝수·홀수 부 번호의 의미는?
> A: 2.6 이전에는 부 번호가 짝수면 안정 버전, 홀수면 개발 버전이었다. 현재는 주.부.패치 형식만 쓰고 짝·홀 규칙은 없다.

**다음으로 갈 기준:** 라이선스 여섯 개를 공개 의무 순서로 늘어놓고, 배포판 이름을 들으면 패키지 도구를 바로 말할 수 있으면 다음 편으로 간다: [2편 · 리눅스 설치](/lectures/grade-mukhnzii/semester-certificate/subject-linux-master-2/lecture-02).

## 정답과 해설

1. **셸(Shell)** — 명령어 해석기. 커널은 하드웨어와 자원을 관리한다.
2. 커널 대부분이 **C 언어**로 작성되어 있기 때문이다. 아키텍처에 의존하는 부분만 다시 쓰면 된다.
3. **모놀리식 커널**이다. 기능을 **커널 모듈(LKM)** 로 만들어 `modprobe`·`insmod`로 재부팅 없이 올린다.
4. **리처드 스톨먼** — 1983년 GNU 프로젝트, 1985년 FSF 설립.
5. **이식성** — 하드웨어에 묶인 어셈블리어 대신 C로 작성해 다른 기계로 옮기기 쉬워졌다.
6. 부 번호 5가 홀수이므로 **개발 버전**이다. (2.4, 2.6은 안정 버전)
7. **카피레프트(Copyleft)**.
8. **MPL(Mozilla Public License)** — 수정한 파일만 공개하면 된다.
9. **GPL 버전 2(GPLv2)**.
10. **.deb 패키지, apt(apt-get)** — Ubuntu 기반 Debian 계열.
11. **Rocky Linux, AlmaLinux**.
12. **Slackware** (1993년 패트릭 볼커딩).

## PART 1 · 마스터플랜 수립

## 1. 분석 마스터플랜이란

**절차:** ==blue:분석 과제 도출 → 우선순위 평가 → 우선순위 정련(적용 범위·방식 고려) → 분석 구현 로드맵 수립==

- **ISP(Information Strategy Planning, 정보전략계획):** 정보기술·시스템을 전략적으로 활용하기 위해 ==조직의 내·외부 환경을 분석하고 중장기 마스터플랜을 수립하는 절차==. 분석 마스터플랜도 이 틀을 빌려 온다.
- **일반 IT 프로젝트 우선순위 기준:** **전략적 중요도**(전략적 필요성 + 시급성), **실행 용이성**(투자 용이성 + 기술 용이성), 비즈니스 성과·ROI.
- **로드맵 수립 시 고려:** 업무 내재화 적용 수준, 분석 데이터 적용 수준, 기술 적용 수준.

## 2. ROI 관점에서 본 빅데이터 4V

| 요소 | 해당 V | 우선순위 기준 |
| --- | --- | --- |
| **투자 비용 요소 (Investment)** | ==blue:Volume · Variety · Velocity== | **난이도** — 데이터 획득·저장·가공 비용, 분석 적용 비용, 분석 수준 |
| **비즈니스 효과 (Return)** | ==blue:Value== | **시급성** — 전략적 중요도, 목표 가치(KPI) |

## 3. 시급성 · 난이도 우선순위 사분면 (포트폴리오 사분면 분석)

교재 그림 그대로 **세로축은 난이도**(위가 어려움, 아래가 쉬움), **가로축은 시급성**(왼쪽이 현재, 오른쪽이 미래)이다.

| 난이도 ↓ / 시급성 → | 현재 (시급) | 미래 (덜 시급) |
| --- | --- | --- |
| **어려움** | **Ⅰ** 전략적 중요도 높음, 시급하지만 난이도 높음 | **Ⅱ** 중장기 관점에서 추진, 난이도 높음 ← 가장 나중 |
| **쉬움** | **Ⅲ** 전략적 중요도 높음, 난이도 낮아 바로 적용 ← 가장 먼저 | **Ⅳ** 중장기 관점, 과제를 바로 적용 가능 |

- ==yellow:Ⅲ(현재·쉬움)이 1순위, Ⅱ(미래·어려움)가 마지막.==
- **우선순위 기준을 시급성**에 둘 때: ==blue:Ⅲ → Ⅳ → Ⅱ==
- **우선순위 기준을 난이도**에 둘 때: ==blue:Ⅲ → Ⅰ → Ⅱ==
- 외우기: 처음 Ⅲ, 끝 Ⅱ는 고정이고 가운데만 바뀐다. ==기준으로 고른 축을 따라 한 칸 이동한다고 기억==하면 된다 — 가로축(시급성)을 따라 Ⅲ에서 Ⅳ로, 세로축(난이도)을 따라 Ⅲ에서 Ⅰ로.

> [!NOTE]
> "시급성 기준인데 왜 덜 시급한 Ⅳ가 둘째일까?"가 가장 많이 헷갈리는 지점이다. 의미를 따지기보다 **그림의 축 이동**으로 외우는 것이 안전하다. 시험은 거의 항상 순서 숫자(3-4-2, 3-1-2)를 묻는다.
>
> 또한 Ⅰ처럼 시급하지만 어려운 과제도 ==경영진의 의사결정에 따라 우선순위를 조정==할 수 있다. 데이터 양·특성이나 분석 범위를 줄여 난이도를 낮추면 Ⅲ처럼 다룰 수 있다.

> [!TRAP]
> ==red:사분면 번호는 수학의 사분면 위치와 다르다.== 왼쪽 위가 Ⅰ, 오른쪽 위가 Ⅱ, 왼쪽 아래가 Ⅲ, 오른쪽 아래가 Ⅳ다. "시급성 기준일 때 두 번째로 수행할 영역"은 **Ⅳ**, "난이도 기준일 때 두 번째"는 **Ⅰ**.

## 4. 이행 계획 수립

- **로드맵:** 목표 달성을 위한 방향과 일정을 시각적으로 표현한 문서. 단계별로 추진 과제·목표·일정을 정의한다.
- **세부 이행 계획:** 폭포수 방식도 쓰지만, 반복적인 정련으로 완성도를 높이는 방식을 주로 쓴다. 단, 모든 단계를 반복하는 것이 아니라 ==데이터 수집·확보와 분석은 순차로, 모델링 단계만 반복==하는 **혼합형**을 많이 적용한다.

## PART 2 · 분석 거버넌스 체계

## 5. 분석 거버넌스 체계의 구성요소

==blue:조직(Organization) · 프로세스(Process) · 시스템(System) · 데이터(Data) · 분석 관련 교육 및 마인드 육성 체계(Human Resource)==

> [!CONCEPT]
> **분석 거버넌스** — 기업에서 데이터 분석을 지속적으로 수행하고 의사결정에 활용하기 위한 ==관리 체계==. 단발성 분석이 아니라 분석 문화가 정착되도록 하는 틀이다.

## 6. 데이터 분석 수준 진단

**분석 준비도(Readiness)** 와 **분석 성숙도(Maturity)** 를 함께 진단해 현재 위치를 파악한다.

### 분석 준비도 — 6개 영역

| 영역 | 진단 항목 예 |
| --- | --- |
| **분석 업무 파악** | 발생한 사실 분석, 예측, 시뮬레이션, 최적화 업무, 정기적 개선 |
| **인력 및 조직** | 분석 전문가 직무·교육, 관리자의 분석 능력, 전사 분석 업무 총괄 조직, 경영진의 이해 |
| **분석 기법** | 업무별 적합한 기법, 기법 라이브러리, 효과성 평가, 정기적 개선 |
| **분석 데이터** | 데이터 충분성·신뢰성·적시성, 비정형 데이터 관리, 외부 데이터 활용, **기준 데이터 관리(MDM)** |
| **분석 문화** | 사실 기반 의사결정, 관리자의 데이터 중시, 회의에서 데이터 활용, 경영진의 직관보다 데이터 |
| **IT 인프라** | 운영 시스템 데이터 통합, EAI·ETL 등 데이터 유통, 분석 전용 서버·스토리지, 빅데이터·통계 분석 환경 |

외우기: ==blue:업무 · 인력조직 · 기법 · 데이터 · 문화 · IT 인프라==

### 분석 성숙도 — CMMI 기반 4단계

**CMMI(Capability Maturity Model Integration)** 를 응용해 **비즈니스·조직 및 역량·IT** 세 부문으로 평가한다.

| 단계 | 설명 | 비즈니스 | 조직·역량 | IT |
| --- | --- | --- | --- | --- |
| **도입** | 분석 시작, 환경·시스템 구축 | 실적·통계 보고 | 일부 부서 담당자 역량 | DW, DM, ETL, OLAP |
| **활용** | 분석 결과를 업무에 적용 | 미래 결과 예측, 시뮬레이션 | 전문 담당 부서, 분석 기법 도입 | 실시간 대시보드, 통계 분석 환경 |
| **확산** | 전사 차원에서 관리·공유 | 전사 성과 실시간 분석, 분석 규칙·이벤트 관리 | 전사 모든 부서 수행, 분석 COE 조직 | 빅데이터 관리 환경, 시뮬레이션·최적화, 비주얼 분석, 분석 전용 서버 |
| **최적화** | 혁신·성과 향상에 기여 | 외부 환경 분석 활용, 최적화 업무 적용 | 데이터 사이언스 그룹, 경영진 분석 활용 | 분석 협업 환경, **분석 Sandbox**, 프로세스 내재화 |

==blue:도입 → 활용 → 확산 → 최적화== ("도활확최")

### 분석 수준 진단 결과 — 성숙도 사분면

가로축 **준비도**(오른쪽이 높음), 세로축 **성숙도**(위가 높음).

| | 준비도 낮음 | 준비도 높음 |
| --- | --- | --- |
| **성숙도 높음** | **정착형** | **확산형** |
| **성숙도 낮음** | **준비형** | **도입형** |

| 유형 | 상태 |
| --- | --- |
| **준비형** (준비도↓ 성숙도↓) | 데이터·조직·인력·분석 업무·기법이 적용되지 않아 **사전 준비가 필요** |
| **정착형** (준비도↓ 성숙도↑) | 준비도는 낮지만 조직·인력·분석 업무·기법을 **제한적으로 사용** 중, 1차 정착 필요 |
| **도입형** (준비도↑ 성숙도↓) | 분석 업무·기법은 부족하지만 **조직·인력 등 준비도가 높아** 바로 도입 가능 |
| **확산형** (준비도↑ 성숙도↑) | 6개 분석 구성요소를 **모두 갖추고** 부분적으로도 확산 가능 |

> [!TRAP]
> ==red:정착형은 "성숙도 높음·준비도 낮음", 도입형은 "준비도 높음·성숙도 낮음".== 이름의 느낌("도입"이 초기 같아서)으로 고르면 틀린다. 준비도가 x축, 성숙도가 y축인지 먼저 확인한다.

## 7. 분석 지원 인프라 방안

- 개별 시스템을 따로 만들기보다 ==확장성을 고려한 플랫폼 구조==를 적용해 **중앙 집중적**으로 관리한다.
- **분석 플랫폼:** 데이터 분석에 필요한 프레임워크와 기반을 제공하는 환경.
  - **협의의 분석 플랫폼:** 데이터 처리 프레임워크, 분석 엔진, 분석 라이브러리
  - **광의의 분석 플랫폼:** 협의의 플랫폼 + 분석 서비스 제공 엔진, 분석 애플리케이션, 분석 서비스 API, 하드웨어·운영체제
- 빅데이터 플랫폼 계층: ==blue:Infrastructure(하위) → Platform(중간) → Software(상위)==

> [!TRAP]
> ==red:광의의 분석 플랫폼은 협의의 분석 플랫폼을 포함한다.== "분석 엔진, 분석 라이브러리"만 있으면 협의, 하드웨어·OS·애플리케이션까지 있으면 광의.

## 8. 데이터 거버넌스

> [!CONCEPT]
> **데이터 거버넌스(Data Governance)** — ==전사 차원의 모든 데이터에 대해 정책·지침·표준·전략을 수립하고, 이를 운영하기 위한 조직과 서비스를 구축==하는 것.

- **구성요소:** ==blue:원칙(Principle) · 조직(Organization) · 프로세스(Process)== ("원조프")
  - 원칙: 데이터를 유지·관리하는 지침과 가이드 (보안, 품질 기준, 변경 관리)
  - 조직: 데이터 관리자, DB 관리자, 데이터 아키텍트 등
  - 프로세스: 데이터 관리 활동과 체계
- **중요 관리 대상:** **마스터 데이터**(처리의 기준이 되는 자료), **메타데이터**, **데이터 사전**(DB에 저장된 정보 요약)

**데이터 거버넌스 체계**

| 체계 | 내용 |
| --- | --- |
| **데이터 표준화** | 데이터 표준 용어 설정, 명명 규칙, 메타데이터·데이터 사전 구축 |
| **데이터 관리 체계** | 메타데이터·데이터 사전의 관리 원칙 수립, 항목별 관리자 지정 |
| **데이터 저장소 관리** | 메타데이터·표준 데이터를 관리하는 전사 저장소 구성, 워크플로·관리용 응용 SW |

- **빅데이터 거버넌스:** 기존 데이터 거버넌스 + 빅데이터의 효율적 관리, 다양한 데이터 관리 체계, 데이터 최적화, 정보보호, 데이터 카테고리별 관리 책임자 지정. ==red:빅데이터는 양이 방대하므로 ERD 같은 체계를 모든 데이터에 적용하기보다, 산업 분야별·데이터 유형별로 차별화한 관리가 필요==하다.

## 9. 분석 조직 구조

**DSCoE(Data Science Center of Excellence):** 분석 전문 조직.

| 구조 | 형태 | 장점 | 단점 |
| --- | --- | --- | --- |
| **집중형** | 별도의 독립 분석 조직(DSCoE)이 전사 분석 업무를 **일괄 담당** | 전략적 중요도에 따라 우선순위를 정해 추진 | 현업 부서와 **업무가 이원화·중복**될 가능성 |
| **기능형** | 별도 분석 조직 **없이** 각 부서에서 직접 분석 | 현업에 맞는 분석 | **전사적 관점**의 핵심 분석 어려움, 과거 실적 분석에 머물기 쉬움 |
| **분산형** | 분석 조직 인력을 **현업 부서에 배치** | 분석 결과를 **신속하게 실무에 적용**, 전사 차원의 우선순위 수행 | 부서 간 역할 분담을 명확히 해야 함 |

> [!TRAP]
> ==red:"이원화·중복" → 집중형, "DSCoE 없음" → 기능형, "현업 배치·신속 적용" → 분산형.== 키워드로 바로 고른다.

**분석 인력 구성:** 비즈니스 인력, IT 기술 인력, 분석 전문 인력, 변화 관리 인력, 교육 담당 인력 등이 함께 필요하다.

> Q: 시급성 우선과 난이도 우선의 사분면 순서는?
> A: 시급성 우선 3 → 4 → 2, 난이도 우선 3 → 1 → 2. 3사분면(시급·쉬움)이 처음, 2사분면(미래·어려움)이 마지막.

> [!FLASHCARD]
> Q: 분석 거버넌스 체계의 구성요소 다섯 가지는?
> A: 조직, 프로세스, 시스템, 데이터, 분석 관련 교육 및 마인드 육성 체계(인적자원).

> [!FLASHCARD]
> Q: 분석 준비도의 6개 영역은?
> A: 분석 업무 파악, 인력 및 조직, 분석 기법, 분석 데이터, 분석 문화, IT 인프라.

> [!FLASHCARD]
> Q: 분석 성숙도 4단계와 각 단계의 대표 IT 요소는?
> A: 도입(DW·DM·ETL·OLAP), 활용(실시간 대시보드·통계 분석 환경), 확산(빅데이터 관리·비주얼 분석·분석 전용 서버), 최적화(분석 Sandbox·분석 협업 환경·프로세스 내재화).

> [!FLASHCARD]
> Q: 성숙도 사분면 네 유형은?
> A: 준비형(준비도·성숙도 모두 낮음), 정착형(준비도 낮고 성숙도 높음), 도입형(준비도 높고 성숙도 낮음), 확산형(둘 다 높음).

> [!FLASHCARD]
> Q: 데이터 거버넌스의 구성요소와 중요 관리 대상은?
> A: 구성요소는 원칙·조직·프로세스, 관리 대상은 마스터 데이터·메타데이터·데이터 사전.

> [!FLASHCARD]
> Q: 집중형·기능형·분산형 분석 조직의 핵심 차이는?
> A: 집중형은 독립 DSCoE가 일괄 담당(업무 이원화 가능), 기능형은 DSCoE 없이 부서별 분석(전사 관점 부족), 분산형은 분석 인력을 현업에 배치(신속한 적용).

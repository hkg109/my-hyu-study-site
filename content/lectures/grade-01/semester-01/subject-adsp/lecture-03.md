## PART 1 · 분석 기획

## 1. 분석 기획이란

> [!CONCEPT]
> **분석 기획** — 실제 분석을 수행하기 전에 ==분석할 과제를 정의하고, 의도한 결과가 나오도록 관리할 방안을 사전에 계획==하는 작업.

분석가에게 필요한 역량: **수학·통계학적 지식** + **IT·프로그래밍 기술** + **해당 비즈니스(도메인)에 대한 이해**, 그리고 이를 아우르는 **균형 잡힌 시각**.

## 2. 분석 주제의 4가지 유형

분석 **대상(What)** 과 분석 **방법(How)** 을 아는지 모르는지로 나눈다.

| | 방법을 앎 (Known) | 방법을 모름 (Unknown) |
| --- | --- | --- |
| **대상을 앎 (Known)** | **최적화(Optimization)** | **솔루션(Solution)** |
| **대상을 모름 (Unknown)** | **통찰(Insight)** | **발견(Discovery)** |

- 대상·방법 모두 앎 → 개선만 하면 됨 → **최적화**
- 대상은 아는데 방법 모름 → 방법을 찾아야 함 → **솔루션**
- 방법은 있는데 대상 모름 → 데이터를 돌려 보며 새 시사점 → **통찰**
- 둘 다 모름 → 처음부터 찾아 나섬 → **발견**

[![분석 대상(What)을 행, 분석 방법(How)을 열로 둔 2×2 표에 최적화·솔루션·통찰·발견을 배치하고, 윗줄은 하향식, 아랫줄은 상향식 접근과 연결한 그림](/materials/diagrams/adsp-l03a-topic-types.svg)](/materials/diagrams/adsp-l03a-topic-types.svg)

*그림 3-1 · 분석 주제의 4가지 유형 — 누르면 원본 크기로 열린다.*

> [!NOTE]
> - **읽는 순서:** 먼저 행(대상을 아는가)을 고르고, 다음에 열(방법을 아는가)을 고른다.
> - **핵심:** 대상을 아는 윗줄(최적화·솔루션)은 하향식, 대상을 모르는 아랫줄(통찰·발견)은 상향식 접근으로 이어진다.
> - **시험 포인트:** 솔루션(대상 ○·방법 ×)과 통찰(대상 ×·방법 ○)을 맞바꾼 보기가 가장 흔한 함정이다.

> [!TRAP]
> ==red:대상을 알고 방법을 모르면 "솔루션", 방법을 알고 대상을 모르면 "통찰".== 둘을 바꿔 놓는 보기가 단골이다. 행·열 중 무엇이 대상인지부터 확인한다.

> [!EXAMPLE]
> **학습용 예시 — 학생 식당**
>
> | 상황 | 유형 |
> | --- | --- |
> | 점심 피크 대기 시간을 줄이려 하고, 대기열 시뮬레이션 기법도 이미 알고 있다 | 최적화 |
> | 잔반을 줄이고 싶은데 어떤 분석을 할지 모른다 | 솔루션 |
> | 결제 데이터에 군집분석을 돌려 보니 "시험 기간 야식족"이라는 집단이 보였다 | 통찰 |
> | 무엇이 문제인지도, 어떻게 볼지도 모른 채 데이터를 탐색한다 | 발견 |

## 3. 목표 시점별 분석 기획 방안

| 구분 | 과제 중심적 접근 (단기) | 장기적 마스터플랜 |
| --- | --- | --- |
| 1차 목표 | **Speed & Test** | **Accuracy & Deploy** |
| 과제 유형 | **Quick-Win** | **Long Term View** |
| 접근 방식 | **Problem Solving** (문제 해결) | **Problem Definition** (문제 정의) |

==yellow:둘은 대립하지 않는다. 당면 과제는 빠르게 해결하면서(Quick-Win), 그 경험을 장기 마스터플랜으로 엮는 혼합 방식이 바람직하다.==

## 4. 분석 기획 시 고려사항

1. **가용 데이터(Available data):** 분석의 기본. 데이터 확보 가능 여부와 유형(정형·반정형·비정형)을 먼저 파악한다.
2. **적절한 유스케이스(Proper use-case):** 이미 잘 구현된 유사 분석 시나리오·솔루션을 최대한 활용한다.
3. **장애요소에 대한 사전 계획(Low barrier of execution):** 비용, 사용자 교육, 변화 관리를 미리 계획하고, 일회성 분석이 아니라 ==조직 역량으로 내재화==한다.

**합리적 의사결정을 가로막는 요소:** 고정관념(stereotype), 편향된 생각(bias), **프레이밍 효과(framing effect)** — 같은 사실도 어떻게 제시되느냐에 따라 판단이 달라지는 현상.

## PART 2 · 분석 방법론

## 5. 분석 방법론의 구성과 모델

**구성요소:** ==blue:상세한 절차 · 방법 · 도구와 기법 · 템플릿과 산출물==

**계층적 프로세스 모델:** ==blue:단계(Phase) → 태스크(Task) → 스텝(Step)==

- **단계:** 프로세스 그룹. 단계별 산출물이 나오고 **베이스라인(baseline)** 으로 관리·버전 관리.
- **태스크:** 단계를 구성하는 단위 활동. 물리적·논리적 산출물.
- **스텝:** 단기간에 수행하는 **WBS의 워크 패키지(work package)**. 입력 → 처리·도구 → 출력.

| 모델 | 특징 | 키워드 |
| --- | --- | --- |
| **폭포수(Waterfall)** | 이전 단계가 끝나야 다음 단계, 문제 시 이전 단계로 피드백 | 순차적, **하향식(Top-down)**, 전통적 |
| **나선형(Spiral)** | 계획 → 위험 분석 → 개발·검증 → 고객 평가를 반복하며 점진 완성 | **위험 관리**, 관리 체계 미비 시 복잡도 상승 |
| **프로토타입(Prototype)** | 일부를 먼저 만들어 보고 보완 | 요구사항 불명확, **상향식** |
| **반복적(Iterative)** | 증분형(기능 단위로 나눠 개발) · 진화형(핵심 먼저, 요구 반영해 진화) | 점진 |
| **애자일(Agile)** | 짧은 주기로 반복하며 고객 피드백 반영 | 유연성 |

> [!TRAP]
> ==red:나선형은 "위험 요소 제거", 프로토타입은 "요구사항 불명확·시제품"이 핵심.== 나선형은 정밀하지만 관리 체계가 없으면 복잡도가 올라가 프로젝트가 진행되지 못할 수 있다.

## 6. KDD 분석 방법론

**KDD(Knowledge Discovery in Databases)** — 1996년 Fayyad가 체계화한, 데이터에서 패턴을 찾는 프로세스.

==blue:데이터셋 선택 → 데이터 전처리 → 데이터 변환 → 데이터 마이닝 → 결과 평가== ("선전변마평")

| 단계 | 하는 일 |
| --- | --- |
| **데이터셋 선택(Selection)** | 비즈니스 도메인 이해와 목표 설정 후, DB에서 분석 대상 데이터 선택 |
| **데이터 전처리(Preprocessing)** | **잡음·이상값·결측값**을 식별하고 정제 |
| **데이터 변환(Transformation)** | 분석 목적에 맞게 **변수 선택, 차원 축소** |
| **데이터 마이닝(Data Mining)** | 목적에 맞는 알고리즘을 골라 패턴 탐색 |
| **결과 평가(Interpretation/Evaluation)** | 결과 해석·평가, 부족하면 앞 단계 반복 |

> [!TRAP]
> ==red:이상값·잡음 처리는 "전처리", 변수 선택·차원 축소는 "변환"==이다.

## 7. CRISP-DM 분석 방법론

**CRISP-DM(Cross Industry Standard Process for Data Mining)** — 1996년 유럽연합 프로젝트에서 시작. **4레벨 구조**: ==blue:단계(Phases) → 일반화 태스크(Generic Tasks) → 세분화 태스크(Specialized Tasks) → 프로세스 실행(Process Instances)==

**6단계:** ==blue:업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개== — 단계 간 **피드백(되돌아가기)** 이 있다.

| 단계 | 주요 태스크 |
| --- | --- |
| **업무 이해** (Business Understanding) | 업무 목적 파악, 상황 파악, 데이터 마이닝 목표 설정, 프로젝트 계획 수립 |
| **데이터 이해** (Data Understanding) | 초기 데이터 수집, 데이터 기술 분석, **데이터 탐색(EDA)**, 데이터 품질 확인 |
| **데이터 준비** (Data Preparation) | 데이터셋 선택, 데이터 정제, 분석용 데이터셋 편성, 데이터 통합, 데이터 포맷팅 |
| **모델링** (Modeling) | 모델링 기법 선택, 모델 테스트 계획 설계, 모델 작성, **모델 평가** |
| **평가** (Evaluation) | 분석 결과 평가, 모델링 과정 평가, **모델 적용성 평가** |
| **전개** (Deployment) | 전개 계획 수립, 모니터링·유지보수 계획, 프로젝트 종료 보고서, 프로젝트 리뷰 |

[![CRISP-DM 6단계를 위에서 아래로 놓고 단계별 태스크를 적은 뒤, 업무 이해↔데이터 이해와 데이터 준비↔모델링의 왕복, 평가에서 업무 이해로 되돌아가는 피드백을 점선으로 그린 그림](/materials/diagrams/adsp-l03b-crisp-dm.svg)](/materials/diagrams/adsp-l03b-crisp-dm.svg)

*그림 3-2 · CRISP-DM 6단계와 피드백 — 누르면 원본 크기로 열린다.*

> [!NOTE]
> - **읽는 순서:** 실선을 따라 ①에서 ⑥으로 내려간 뒤, 오른쪽 점선으로 어디서 어디로 되돌아가는지 본다.
> - **핵심:** 업무 이해와 데이터 이해, 데이터 준비와 모델링은 서로 오가고, 평가에서 업무 목표를 못 채우면 업무 이해로 돌아간다.
> - **시험 포인트:** 굵게 표시한 태스크 세 개 — 데이터 탐색은 데이터 이해, 모델 평가는 모델링, 모델 적용성 평가는 평가 단계다.

> [!TRAP]
> ==red:"모델 평가"는 모델링 단계, "모델 적용성 평가"는 평가 단계다.== 데이터 탐색(EDA)과 품질 확인은 "데이터 준비"가 아니라 "데이터 이해" 단계다. 평가 결과가 업무 목표를 못 채우면 **업무 이해로 되돌아갈 수 있다.**

### KDD · CRISP-DM · SEMMA 대응

| KDD | CRISP-DM | SEMMA (SAS) |
| --- | --- | --- |
| (도메인 이해) | 업무 이해 | — |
| 데이터셋 선택 + 전처리 | 데이터 이해 | **Sample**(추출) + **Explore**(탐색) |
| 데이터 변환 | 데이터 준비 | **Modify**(변환) |
| 데이터 마이닝 | 모델링 | **Model**(모델링) |
| 결과 평가 | 평가 | **Assess**(평가) |
| (활용) | 전개 | — |

**SEMMA:** ==blue:Sample → Explore → Modify → Model → Assess== — SAS사가 만든, 기술·통계 중심 방법론.

## 8. 빅데이터 분석 방법론

==blue:분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개==

| 단계 | 태스크 | 핵심 산출물·키워드 |
| --- | --- | --- |
| **분석 기획** (Planning) | 비즈니스 이해 및 범위 설정 / 프로젝트 정의 및 계획 수립 / 프로젝트 위험계획 수립 | **SOW**(작업 명세서), **WBS**(작업 분할 구조), 위험 대응 |
| **데이터 준비** (Preparing) | 필요 데이터 정의 / 데이터 스토어 설계 / 데이터 수집 및 정합성 점검 | 정형·비정형 저장소 설계, 크롤링·API·ETL |
| **데이터 분석** (Analyzing) | 분석용 데이터 준비 / 텍스트 분석 / 탐색적 분석 / 모델링 / 모델 평가 및 검증 | 데이터 분할, 추가 데이터 필요 시 **데이터 준비로 피드백** |
| **시스템 구현** (Developing) | 설계 및 구현 / 시스템 테스트 및 운영 | 단순 분석으로 끝나면 생략 가능 |
| **평가 및 전개** (Deploying) | 모델 발전 계획 수립 / 프로젝트 평가 및 보고 | 지식 자산화 |

**위험 대응 방법:** ==blue:회피(Avoid) · 전이(Transfer) · 완화(Mitigate) · 수용(Accept)== ("회전완수")

## 9. 하향식 접근법 (Top-down)

> [!CONCEPT]
> **하향식 접근** — ==문제가 주어진 상태에서 해법을 찾아가는 방식==. 분석적으로 사물을 인식하는 **Why** 관점. 분석 대상(What)을 알 때, 즉 **최적화·솔루션** 유형에 쓴다. 주로 **지도 학습**.

==blue:문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토==

### ① 문제 탐색 (Problem Discovery)

빠짐없이 문제를 도출하는 것이 중요하며, 세부 솔루션보다 ==문제를 해결했을 때 생기는 가치==에 초점을 둔다.

- **비즈니스 모델 캔버스 기반:** 9블록을 단순화한 ==blue:업무 · 제품 · 고객 · 규제와 감사 · 지원 인프라== 5영역
- **외부 참조 모델 기반:** 유사·동종 업계 사례 벤치마킹, 분석 유스케이스 정의
- **분석 기회 발굴의 범위 확장**

| 관점 | 세부 영역 |
| --- | --- |
| **거시적 관점** | ==blue:STEEP — 사회(Social) · 기술(Technological) · 경제(Economic) · 환경(Environmental) · 정치(Political)== |
| **경쟁자 확대 관점** | 대체재(Substitute) · 경쟁자(Competitor) · 신규 진입자(New entrant) |
| **시장의 니즈 탐색 관점** | 고객(Customer) · 채널(Channel) · 영향자들(Influencer) |
| **역량의 재해석 관점** | 내부 역량 · 파트너와 네트워크 |

> [!TRAP]
> ==red:대체재·경쟁자·신규 진입자는 "경쟁자 확대 관점", 고객·채널·영향자는 "시장의 니즈 탐색 관점"==이다. 섞어서 낸다.

### ② 문제 정의 (Problem Definition)

==비즈니스 문제를 데이터 분석 문제로 변환==한다. 예: "고객 이탈 증가"(비즈니스 문제) → "이탈 가능성이 높은 고객을 예측하는 분류 모델"(분석 문제). 최종 사용자 관점에서 정의하고, 필요한 데이터와 기법(How)을 정의하기 위한 단계다.

### ③ 해결방안 탐색 (Solution Search)

| | 분석 역량 확보 | 분석 역량 미확보 |
| --- | --- | --- |
| **기존 시스템 활용** | 기존 시스템 개선·활용 | 교육 및 채용을 통한 역량 확보 |
| **신규 도입** | 시스템 고도화 | 전문 업체 활용(Sourcing) |

### ④ 타당성 검토 (Feasibility Study)

- **경제적 타당성:** 비용 대비 편익 분석
- **데이터 및 기술적 타당성:** 데이터 존재 여부, 분석 시스템 환경, 분석 역량 확보 방안
- 도출된 대안을 평가해 최적 대안을 **분석 과제 정의서**로 만든다.

## 10. 상향식 접근법 (Bottom-up)

> [!CONCEPT]
> **상향식 접근** — 문제 정의 자체가 어려울 때 ==데이터를 기반으로 문제를 탐색하고 지속적으로 개선==하는 방식. 사물을 있는 그대로 보는 **What** 관점. 분석 대상을 모를 때, 즉 **통찰·발견** 유형에 쓴다. 주로 **비지도 학습**.

- 절차 예: 프로세스 분류 → 프로세스 흐름 분석 → 분석 요건 식별 → 분석 요건 정의
- **프로토타이핑 접근법:** 일단 분석을 시도해 결과를 보고 반복 개선. 사용자 요구가 불명확하거나, 필요한 데이터가 있는지 불확실하거나, 새로운 시도일 때 유용하다.
- 장바구니 데이터에 연관분석을 돌려 "어떤 품목이 함께 팔리는가"를 먼저 발견하는 식이다.

| 구분 | 지도 학습 (Supervised) | 비지도 학습 (Unsupervised) |
| --- | --- | --- |
| 데이터 | 입력 + **정답(레이블)** | 입력만 |
| 목적 | 예측·분류 | 구조·패턴 발견 |
| 기법 | 회귀, 분류, 의사결정나무, KNN, SVM, 인공신경망 | 군집분석, 연관분석, 차원축소(PCA), SOM |
| 접근 | 하향식 | 상향식 |

## 11. 혼합 접근과 디자인 씽킹

- **발산(Diverge) 단계:** 상향식으로 가능한 옵션을 넓게 도출
- **수렴(Converge) 단계:** 하향식으로 도출된 옵션을 분석·검증해 좁힘
- **디자인 씽킹(Design Thinking):** 사용자 공감에서 출발해 발산과 수렴을 반복 — ==blue:공감 → 문제 정의 → 아이디어 도출 → 프로토타입 → 테스트==

> [!NOTE]
> - **읽는 순서:** 위쪽 두 열에서 두 접근의 관점·유형·학습 방식을 비교하고, 아래 다이아몬드에서 둘이 어떻게 합쳐지는지 본다.
> - **핵심:** 하향식은 Why·지도 학습·문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토, 상향식은 What·비지도 학습·프로토타이핑이다.

## 12. 분석 과제 정의서와 5가지 주요 특성

**분석 과제 정의서:** 필요한 소스 데이터, 분석 방법, 데이터 입수·분석 난이도, 분석 수행 주기, 결과 검증 오너십, 상세 분석 과정 등을 정의. ==이해관계자가 프로젝트 방향을 설정하고 성공 여부를 판단하는 기준==이 된다.

**분석 과제의 5가지 주요 특성(관리 영역)**

| 특성 | 고려할 점 |
| --- | --- |
| **Data Size** (데이터 크기) | 지속적으로 생성되는 데이터의 양 |
| **Data Complexity** (데이터 복잡성) | 정형·비정형, 여러 시스템에 흩어진 데이터 통합 |
| **Speed** (속도) | 실시간인가 배치인가, 결과 활용 시점 |
| **Analytic Complexity** (분석 복잡성) | 정확도와 복잡도의 **트레이드오프**, 해석 가능성 |
| **Accuracy & Precision** (정확도·정밀도) | 둘 사이 트레이드오프 |

> [!NOTE]
> 여기서 **정확도(Accuracy)** 는 모델 예측값과 실제값의 차이가 작은 정도, **정밀도(Precision)** 는 모델을 반복 실행했을 때 결과의 편차가 작은 정도다. 활용 측면에서는 Accuracy, 안정성 측면에서는 Precision이 중요하다. ==red:3과목 오분류표의 정확도·정밀도와는 다른 개념==이다.

## 13. 분석 프로젝트 관리 10개 영역

| 영역 | 분석 프로젝트에서의 포인트 |

| **조달** | 외부 데이터 구매, 오픈소스·PoC 등 **외부 소싱** |

| **이해관계자** | 데이터 전문가·현업·의사결정자 등 다양함 |
| 통합 · 자원 · 의사소통 | 프로세스 통합, 전문 인력 확보, 이해관계자 간 공유 |

> [!FLASHCARD]
> Q: CRISP-DM 6단계는?
> A: 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개.

> [!FLASHCARD]
> Q: CRISP-DM의 4레벨 구조는?
> A: 단계(Phases) → 일반화 태스크(Generic Tasks) → 세분화 태스크(Specialized Tasks) → 프로세스 실행(Process Instances).

> [!FLASHCARD]
> Q: KDD 5단계와 각 단계의 핵심 작업은?
> A: 데이터셋 선택 → 전처리(잡음·이상값·결측값 처리) → 변환(변수 선택·차원 축소) → 데이터 마이닝 → 결과 평가.

> [!FLASHCARD]
> Q: 빅데이터 분석 방법론 5단계와 분석 기획 단계의 태스크는?
> A: 분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개. 분석 기획은 비즈니스 이해·범위 설정(SOW), 프로젝트 정의·계획(WBS), 위험계획 수립.

> [!FLASHCARD]
> Q: 하향식 문제 탐색에서 비즈니스 모델 캔버스를 단순화한 5영역은?
> A: 업무, 제품, 고객, 규제와 감사, 지원 인프라.

> [!FLASHCARD]
> Q: 해결방안 탐색 매트릭스의 네 칸은?
> A: 역량 확보 + 기존 시스템 → 기존 시스템 개선 활용, 역량 미확보 + 기존 시스템 → 교육·채용, 역량 확보 + 신규 도입 → 시스템 고도화, 역량 미확보 + 신규 도입 → 전문 업체 소싱.

> [!FLASHCARD]
> Q: 나선형 모델과 프로토타입 모델의 핵심 차이는?
> A: 나선형은 반복하며 위험 요소를 분석·제거하는 데 초점, 프로토타입은 요구사항이 불명확할 때 시제품을 먼저 만들어 보완하는 데 초점.

**다음으로 갈 기준:** 방법론 네 개의 단계를 막힘없이 쓰고, CRISP-DM 태스크 하나를 단계에 꽂을 수 있으면 다음 편으로 간다: [4편 · 분석 마스터플랜](/lectures/grade-01/semester-01/subject-adsp/lecture-04).

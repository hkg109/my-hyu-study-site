# 오버로딩·포인터·동적 메모리

**슬라이드:** Lecture 6 (6주차) · Function Overloading, Pointers and Pointer Arithmetic, The Heap

포인터는 C++에서 처음 배우는 사람이 가장 많이 막히는 곳입니다. 하지만 규칙은 몇 개 안 됩니다. 이 강의는 **변수가 메모리 어디에 사는가**에서 출발해, 그림을 그리며 한 줄씩 따라가는 방식으로 설명합니다. 2026 일정에서 포인터는 **중간고사 범위**입니다.

---

## 학습 흐름

```text
함수 오버로딩 → 모호한 호출
        ↓
메모리와 주소 → 포인터 선언 · 주소 연산자 & · 역참조 * → 포인터 자료형
        ↓
포인터와 함수(call by reference) → const 포인터
        ↓
배열과 포인터 → 포인터 연산 → 포인터 배열 · 이중 포인터 → C 문자열
        ↓
sizeof와 힙 → malloc/calloc/free → new/delete
```

> [!EXAM]
> 포인터 문제는 **그림을 그리면** 틀리지 않습니다. 변수마다 상자를 그리고, 포인터는 화살표로 표시한 뒤 한 줄씩 상자 값과 화살표를 갱신하세요.

## 1. 함수 오버로딩

**함수 오버로딩**은 이름이 같은 함수를 여러 개 두고 **매개변수의 자료형(또는 개수)**으로 구분하는 것입니다. 어느 함수를 쓸지는 **컴파일할 때** 인수를 보고 정합니다.

```cpp
double max(double num1, double num2) { return num1 > num2 ? num1 : num2; }
int    max(int num1, int num2)       { return num1 > num2 ? num1 : num2; }

d = max(2.0, 3.0);   // double 버전
i = max(2, 3);       // int 버전
```

**모호한 호출(ambiguous invocation)** — 맞을 수 있는 함수가 둘 이상인데 어느 쪽이 더 구체적인지 컴파일러가 정하지 못하면 **컴파일 오류**입니다. 캐스트로 풀 수 있습니다.

```cpp
double max(int num1, double num2);
double max(double num1, int num2);
d = max(4.0, 5.0);   // ? 둘 다 한 인수씩 double→int 변환이 필요 → 모호 → 컴파일 오류
d = max((int)4.0, 5.0);   // 첫 번째 버전으로 확정
```

> [!TRAP]
> **반환형만 다른** 함수는 오버로딩이 아닙니다(`int f(int)`와 `double f(int)`는 컴파일 오류). 구분 기준은 매개변수 목록뿐입니다.

### 오버로딩

**이름이 같고 매개변수 목록(개수 또는 자료형)이 다른** 함수를 여러 개 만들 수 있습니다. 컴파일러가 인수의 자료형을 보고 가장 잘 맞는 함수를 고릅니다.

```cpp
void f(int x)    { cout << "int "; }
void f(double x) { cout << "double "; }
void f(char x)   { cout << "char "; }
```

| 호출 | 선택 | 이유 |
| --- | --- | --- |
| `f(3)` | `f(int)` | 정확히 일치 |
| `f(3.0)` | `f(double)` | 정확히 일치 |
| `f('a')` | `f(char)` | 정확히 일치 |
| `f(3.0f)` | `f(double)` | float → double 승격 |
| `f(true)` | `f(int)` | bool → int 승격 |
| `f(3L)` | **컴파일 오류** | long → int / double / char가 모두 "변환"이라 우열이 없음(모호) |

> [!TRAP]
> - **반환형만 다른** 함수는 오버로딩이 아닙니다. `int g();`와 `double g();`는 함께 둘 수 없습니다(컴파일 오류).
> - 매개변수 **이름**만 다른 것도 같은 함수입니다.

### 기본 인수

인수를 생략하면 기본값을 씁니다. 기본값은 **오른쪽 매개변수부터** 채워야 합니다.

```cpp
int add(int a, int b = 10, int c = 100) { return a + b + c; }

add(1);         // 1 + 10 + 100 = 111
add(1, 2);      // 1 + 2 + 100  = 103
add(1, 2, 3);   // 6

int bad(int a = 1, int b);   // 컴파일 오류: 기본값 뒤에 기본값 없는 매개변수
```

> [!TRAP]
> 오버로딩과 기본 인수가 겹치면 모호해집니다. `void k(int);`와 `void k(int, int = 0);`이 함께 있으면 `k(5)`는 둘 다 맞아서 **컴파일 오류**입니다.

> [!QUIZ]
> 위의 `f` 세 개와 `add`가 있을 때 출력을 쓰시오. 컴파일 오류인 호출이 있으면 표시하시오.
>
> ```cpp
> f(3); f(3.0); f('a'); f(3.0f); f(true);
> cout << '\n' << add(1) << ' ' << add(1, 2) << ' ' << add(1, 2, 3);
> f(3L);
> ```

> [!ANSWER]
> ```text
> int double char double int 
> 111 103 6
> ```
>
> `f(3L)`은 세 함수 모두 변환이 필요해 **모호한 호출**이므로 컴파일 오류입니다. 이 줄을 지워야 위 출력이 나옵니다.

## 2. 변수는 메모리에 산다

[![주소 1004에 있는 int x와 주소 1016에 있는 포인터 p를 메모리 표로 그리고 p가 x를 가리키며 *p = 5로 x가 5가 되는 그림](/materials/diagrams/cpp-05-pointer-memory.svg)](/materials/diagrams/cpp-05-pointer-memory.svg)

*그림 5-1 · 포인터는 주소를 담는 변수 — 누르면 원본 크기로 열린다.*


`int n = 42;`라고 쓰면 컴파일러는 메모리 어딘가에 `int` 하나가 들어갈 칸(보통 4바이트)을 잡고, 그 칸에 이름 `n`을 붙이고, 42를 넣습니다. 이 칸에는 **번호(주소)**가 있습니다.

```text
주소      0x1000   0x1004   0x1008
         ┌───────┬───────┬───────┐
         │  42   │   7   │   …   │
         └───────┴───────┴───────┘
이름        n        m
```

- 우리는 평소에 **이름(`n`)**으로 칸을 씁니다.
- 포인터는 이름 대신 **주소(`0x1000`)**로 칸을 다루는 방법입니다.
- 실제 주소 값은 실행할 때마다 다르고 시험에도 나오지 않습니다. 중요한 것은 **"어느 칸을 가리키는가"**라는 관계입니다. 그래서 그림에서는 주소 숫자 대신 **화살표**를 씁니다.

> [!NOTE]
> 왜 굳이 주소로 다룰까요? ① 함수가 **호출한 쪽의 변수를 직접 바꾸게** 하려고(4절), ② **배열을 훑으려고**(5절), ③ 실행 중에 크기가 정해지는 **메모리를 빌리려고**(7절)입니다. 이 세 가지가 포인터를 배우는 이유의 전부입니다.

## 3. 주소와 포인터

### 3-1. 기호 세 개만 기억하기

| 기호 | 어디에 쓰나 | 뜻 | 읽는 법 |
| --- | --- | --- | --- |
| `&x` | 식 안 | 변수 `x`의 **주소** | "x의 주소" |
| `int* p` | 선언 | `p`는 `int`의 주소를 저장하는 **포인터** | "int를 가리키는 포인터 p" |
| `*p` | 식 안 | `p`가 가리키는 곳의 **값**(역참조) | "p가 가리키는 값" |
| `int& r` | 선언 | 참조(별명). 주소 연산자와 **다른** 뜻 | "int 참조 r" (04강) |

> [!TRAP]
> `*`와 `&`는 **선언에 쓰일 때**와 **식에 쓰일 때** 뜻이 다릅니다.
> - 선언 `int* p` → "p는 포인터다" / 식 `*p` → "p가 가리키는 값"
> - 선언 `int& r = x` → "r은 x의 별명이다" / 식 `&x` → "x의 주소"
>
> 줄 맨 앞에 **자료형이 있으면 선언**, 없으면 식이라고 구분하면 됩니다.

### 3-2. 첫 포인터 프로그램

```cpp
#include <iostream>
using namespace std;

int main() {
    int n = 42;
    int* p = &n;          // ① p에 n의 주소를 넣는다 → p는 n을 가리킨다

    cout << n << '\n';    // 42
    cout << *p << '\n';   // 42  ← p가 가리키는 칸(n)의 값

    *p = 100;             // ② p가 가리키는 칸(n)에 100을 넣는다
    cout << n << '\n';    // 100 ← n을 직접 건드리지 않았는데 바뀌었다
}
```

```text
① 직후:   p ──▶ [ n : 42 ]
② 직후:   p ──▶ [ n : 100 ]
```

`*p = 100`은 "p 상자에 100을 넣어라"가 아니라 "**p가 가리키는 상자**에 100을 넣어라"입니다. 그래서 `n`이 바뀝니다.

### 3-3. 포인터를 만들 때 지켜야 할 규칙

- 포인터 자료형은 가리킬 값의 자료형과 맞아야 합니다. `int n; double* d = &n;`은 **컴파일 오류**입니다.
- 아무것도 가리키지 않을 때는 `nullptr`로 초기화합니다.
- 초기화하지 않은 포인터나 `nullptr`을 **역참조하면 UB**(보통 비정상 종료)입니다.
- `int* p = 5;`처럼 정수를 바로 넣는 것은 **컴파일 오류**입니다. 포인터에는 주소만 들어갑니다.

```cpp
int* p = nullptr;     // 빈 쪽지
if (p != nullptr) {   // 쓰기 전에 확인하는 습관
    cout << *p;
}
```

> [!TRAP]
> `int* p, q;`에서 `q`는 포인터가 아니라 **그냥 int**입니다. `*`는 자료형이 아니라 **변수 이름마다** 붙습니다. 두 개 다 포인터로 만들려면 `int *p, *q;`라고 씁니다.

### 3-4. 값 복사와 주소 복사 — 가장 중요한 구분

| 문장 | 무엇을 복사하나 | 그림에서 바뀌는 것 |
| --- | --- | --- |
| `*p = *q;` | q가 가리키는 **값**을 p가 가리키는 칸으로 | **상자 안의 숫자** |
| `p = q;` | q에 적힌 **주소**를 p로 | **화살표 방향** |

```cpp
int a = 1, b = 2;
int* p = &a;
int* q = &b;

*p = *q;   // a = b  → a: 2, 화살표는 그대로
p = q;     // 이제 p도 b를 가리킨다 → 화살표만 옮겨짐
*p = 9;    // b = 9
// 결과: a = 2, b = 9
```

```text
처음:        p ──▶ [a:1]      q ──▶ [b:2]
*p = *q:     p ──▶ [a:2]      q ──▶ [b:2]
p = q:       [a:2]            p ──┐
                              q ──┴▶ [b:2]
*p = 9:      [a:2]            p, q ──▶ [b:9]
```

> [!QUIZ]
> 다음 출력을 쓰시오.
>
> ```cpp
> int a = 10, b = 20;
> int* p = &a;
> int* q = &b;
> *p = *q + 5;
> p = q;
> *p = 7;
> cout << a << ' ' << b << ' ' << *p << ' ' << *q << ' ' << (p == q);
> ```

> [!ANSWER]
> ```text
> 25 7 7 7 1
> ```
>
> | 문장 | 의미 | a | b | p가 가리킴 |
> | --- | --- | ---: | ---: | --- |
> | `*p = *q + 5` | a = b + 5 | 25 | 20 | a |
> | `p = q` | 주소 복사 (화살표 이동) | 25 | 20 | **b** |
> | `*p = 7` | b = 7 | 25 | 7 | b |
>
> `p = q`는 **값이 아니라 주소**를 복사합니다. 이후 `*p`와 `*q`는 같은 변수입니다. `p == q`는 두 주소가 같은지 비교하므로 1(참)입니다.

> [!QUIZ]
> 다음 선언에서 (1) `p[0] == n`의 참·거짓, (2) `p = &k;`의 대입 가능 여부를 쓰고, (3) 배열 `arr`의 `arr[i]`를 포인터 연산으로 쓰시오.
>
> ```cpp
> int n = 3;
> int& k = n;
> int* p = &n;
> ```

> [!ANSWER]
> (1) **참**. `p[0]`은 `*(p + 0)` = `*p` = `n`입니다. (2) **가능**. `k`는 `n`의 별명이므로 `&k`는 `&n`과 같은 주소입니다. (3) `*(arr + i)`.

> [!CHECK]
> 스스로 확인: `int x = 5; int* p = &x; *p = *p * 2;` 뒤에 `x`는? → **10**. `*p * 2`의 앞 `*`는 역참조, 가운데 `*`는 곱셈입니다.

**포인터 자료형은 맞아야 한다** (Lecture 6 슬라이드 16)

```cpp
int n = 5;      double x = 5.0;
int *ptr1;      double *ptr2;
ptr1 = &n;      // OK
ptr2 = &n;      // 컴파일 오류: double 포인터에 int의 주소
ptr1 = &x;      // 컴파일 오류: int 포인터에 double의 주소
```

**초기화하지 않은 포인터** — `int *p; *p = 1;`은 아무 주소에나 1을 씁니다. 운이 나쁘면 "segmentation fault"로 죽고, 더 나쁘면 다른 변수를 조용히 망가뜨려 **틀린 결과로 계속 실행**됩니다.

## 4. 포인터와 함수

[![값으로 받은 swap은 복사본만 바꿔 n과 m이 그대로이고 포인터로 받은 swap은 원본 n과 m을 바꾸는 비교 그림](/materials/diagrams/cpp-05-swap.svg)](/materials/diagrams/cpp-05-swap.svg)

*그림 5-2 · swap(n, m)과 swap(&n, &m) — 누르면 원본 크기로 열린다.*

함수 매개변수를 포인터로 선언하면, 호출할 때 **변수의 주소**를 넘겨 함수가 호출한 쪽 변수를 바꿀 수 있습니다. 슬라이드는 이것을 **call by reference**라고 부릅니다(04강의 참조 매개변수와 같은 효과).

```cpp
void fun(int a, int b, int *p1, int *p2) {
    *p1 = a + b;      // sum에 저장
    *p2 = a * b;      // product에 저장
}
int x = 3, y = 5, sum, product;
fun(x, y, &sum, &product);   // sum = 8, product = 15 — 결과 두 개를 돌려받음
```

### 4-1. 왜 필요한가: 함수는 원래 복사본을 받는다

C++ 함수는 기본적으로 인수를 **복사해서** 받습니다. 그래서 함수 안에서 매개변수를 바꿔도 호출한 쪽 변수는 그대로입니다.

```cpp
void addOne(int x) { x = x + 1; }   // x는 복사본

int main() {
    int a = 5;
    addOne(a);
    cout << a;    // 5 — 복사본만 바뀌었다
}
```

호출한 쪽 변수를 바꾸고 싶으면 **주소를 넘기거나**(포인터), **별명을 넘깁니다**(참조).

```cpp
void addOneP(int* x) { *x = *x + 1; }   // 주소를 받아 그 칸을 바꿈
void addOneR(int& x) { x = x + 1; }     // 별명이라 원본 그 자체

int a = 5;
addOneP(&a);   // 주소를 넘김 → a = 6
addOneR(a);    // 이름 그대로 넘김 → a = 7
```

### 4-2. swap 네 가지 — 시험의 단골

```cpp
void s1(int a, int b)   { int t = a; a = b; b = t; }        // 복사본 교환
void s2(int* a, int* b) { int t = *a; *a = *b; *b = t; }    // 가리키는 값 교환
void s3(int* a, int* b) { int* t = a; a = b; b = t; }       // 지역 포인터만 교환
void s4(int& a, int& b) { int t = a; a = b; b = t; }        // 원본 교환
```

`s3`이 함정입니다. 포인터도 **값으로 전달**되므로, 함수 안의 `a`, `b`는 호출할 때 넘겨준 주소를 **복사한 쪽지**입니다. 쪽지끼리 바꿔 들어도 원래 상자 안의 값은 그대로입니다.

```text
s3 안:   a(쪽지 복사본) ──▶ [x]        b(쪽지 복사본) ──▶ [y]
교환 후:  a ──▶ [y]   b ──▶ [x]      ← 쪽지만 바뀜, x와 y의 값은 그대로
```

| 구분 | 포인터 매개변수 | 참조 매개변수 |
| --- | --- | --- |
| 선언 | `void f(int* p)` | `void f(int& r)` |
| 호출 | `f(&x)` | `f(x)` |
| 안에서 사용 | `*p` | `r` |
| "없음" 표현 | `nullptr` 가능 | 불가(반드시 대상이 있음) |
| 다른 대상으로 바꾸기 | 가능 | 불가 |

> [!QUIZ]
> `int x = 1, y = 2;`에서 시작해 아래를 **차례로** 실행할 때 각 호출 뒤의 `x y`를 쓰시오.
>
> ```cpp
> s1(x, y);   s2(&x, &y);   s3(&x, &y);   s4(x, y);
> ```

> [!ANSWER]
> | 호출 | x y | 이유 |
> | --- | --- | --- |
> | `s1(x, y)` | 1 2 | 값 복사본만 교환 |
> | `s2(&x, &y)` | 2 1 | `*a`, `*b`로 원본 교환 |
> | `s3(&x, &y)` | 2 1 | 포인터 변수(복사본)끼리만 교환, 값은 그대로 |
> | `s4(x, y)` | 1 2 | 참조로 원본 교환 |
>
> `s3`이 함정입니다. 포인터도 **값으로 전달**되므로 함수 안에서 `a = b`를 해도 호출한 쪽에는 영향이 없습니다.

### 4-3. 포인터 매개변수로 여러 결과 돌려주기

`return`은 값을 하나만 돌려줍니다. 결과가 둘 이상이면 **결과를 넣을 칸의 주소**를 받아서 채웁니다.

```cpp
void minmax(const int a[], int n, int* mn, int* mx) {
    *mn = *mx = a[0];
    for (int i = 1; i < n; i++) {
        if (a[i] < *mn) *mn = a[i];
        if (a[i] > *mx) *mx = a[i];
    }
}

int arr[4] = {4, -2, 9, 0};
int lo, hi;
minmax(arr, 4, &lo, &hi);     // lo = -2, hi = 9
```

`&lo`, `&hi`를 넘겼으므로 함수 안의 `*mn`, `*mx`는 곧 `lo`, `hi`입니다.

포인터에는 고정할 수 있는 것이 **두 가지** 있습니다.

1. **가리키는 값** — 이 포인터로 값을 바꾸지 못하게
2. **포인터 자체(화살표)** — 다른 곳을 가리키지 못하게

규칙은 하나입니다. `const`가 `*`의 **왼쪽**에 있으면 **값**을, **오른쪽**에 있으면 **포인터 자체**를 고정합니다.

```text
const int *  p      → const가 * 왼쪽  → 값 고정     ("상수를 가리키는 포인터")
      int *  const p → const가 * 오른쪽 → 화살표 고정 ("상수 포인터")
```

| 선언 | `*p = 5` (값 변경) | `p = &m` (가리키는 곳 변경) | 읽는 법 |
| --- | :---: | :---: | --- |
| `int* p` | O | O | 보통 포인터 |
| `const int* p` (= `int const* p`) | **X** | O | 상수를 가리키는 포인터 |
| `int* const p` | O | **X** | 상수 포인터 (선언할 때 초기화 필수) |
| `const int* const p` | **X** | **X** | 둘 다 고정 |

> [!NOTE]
> **뒤에서부터 읽기** 요령: `int* const p` → "p는 const인 포인터, int를 가리키는". `const int* p` → "p는 포인터, const int를 가리키는". 영어 선언문을 오른쪽에서 왼쪽으로 읽으면 뜻이 맞아떨어집니다.

`const int*`가 **const가 아닌 변수**를 가리키는 것은 괜찮습니다. "이 포인터로는 바꾸지 않겠다"는 약속일 뿐, 변수 자체는 이름으로 바꿀 수 있습니다. 반대로 `const` 변수를 **보통 포인터**로 가리키면 그 포인터로 상수를 바꿀 수 있게 되므로 컴파일 오류입니다.

```cpp
int n = 1;
const int* r = &n;     // OK
n = 2;                 // OK: 이름으로는 바꿀 수 있음
// *r = 3;             // 오류: r로는 못 바꿈

const int c = 9;
int* p4 = &c;          // 컴파일 오류: const 값을 바꿀 수 있는 포인터로 가리킬 수 없음
const int* p5 = &c;    // OK
```

> [!QUIZ]
> 컴파일 오류가 나는 줄을 모두 고르시오.
>
> ```cpp
> int n = 1, m = 2;
> const int* p1 = &n;
> *p1 = 5;               // (1)
> p1 = &m;               // (2)
> int* const p2 = &n;
> *p2 = 5;               // (3)
> p2 = &m;               // (4)
> const int* const p3 = &n;
> *p3 = 5;               // (5)
> p3 = &m;               // (6)
> const int c = 9;
> int* p4 = &c;          // (7)
> const int* p5 = &c;    // (8)
> ```

> [!ANSWER]
> 오류: **(1), (4), (5), (6), (7)**. `const int*`는 값을, `int* const`는 주소를 바꿀 수 없습니다. `const int*`가 `n`처럼 const가 아닌 변수를 가리키는 것은 괜찮습니다(그 포인터로 바꿀 수 없을 뿐).

## 5. 배열과 포인터

[![int 배열 a 다섯 칸 위에서 ptr이 a 0을, ptr+2가 a 2를, ptr+4가 a 4를 가리키는 그림](/materials/diagrams/cpp-05-pointer-arithmetic.svg)](/materials/diagrams/cpp-05-pointer-arithmetic.svg)

*그림 5-3 · 포인터 연산은 원소 단위 — 누르면 원본 크기로 열린다.*

슬라이드: “**배열 이름은 기본적으로 const 포인터**(주소가 고정된 포인터)다.” 그래서 `int *x; int a[10]; x = a;`는 OK이고 `x[2]`는 `a[2]`와 같습니다. 04강에서 배열을 함수에 넘기면 원본이 바뀌었던 이유가 이것입니다 — **시작 주소**가 넘어갔기 때문입니다.

```cpp
void print_array(int a[], int len) {          // 배열 버전
    for (int i = 0; i < len; i++) std::cout << i << " " << a[i];
}
void print_array(int *a, int len) {           // 포인터 버전 (같은 뜻)
    for (int i = 0; i < len; i++) std::cout << i << " " << *a++;
}
```

### 5-1. 배열 이름은 첫 원소의 주소처럼 쓰인다

배열 `int a[5]`는 메모리에 칸 다섯 개가 **붙어서** 놓입니다. 배열 이름 `a`는 대부분의 식에서 **첫 원소의 주소**(`&a[0]`)로 바뀝니다.

```text
          a[0]  a[1]  a[2]  a[3]  a[4]
         ┌─────┬─────┬─────┬─────┬─────┐
         │  1  │  2  │  3  │  4  │  5  │
         └─────┴─────┴─────┴─────┴─────┘
          ▲     ▲           ▲
          a    a+1         a+3
```

그래서 다음 세 줄은 모두 같은 규칙입니다.

```text
a[i]  ==  *(a + i)        &a[i]  ==  a + i        p[i]  ==  *(p + i)
```

대괄호 `a[i]`는 사실 "**a에서 i칸 간 곳의 값**"을 줄여 쓴 것입니다.

### 5-2. 포인터 연산: +1은 "한 칸"

`p + 1`은 주소를 1바이트가 아니라 **원소 하나만큼**(int면 4바이트) 이동합니다. 자료형을 알기 때문에 컴파일러가 알아서 칸 크기를 곱해 줍니다.

```cpp
int a[5] = {1, 2, 3, 4, 5};
int* p = a;            // p는 a[0]을 가리킴

cout << *p << '\n';        // 1
cout << *(p + 2) << '\n';  // 3   ← 두 칸 뒤
p++;                       // 이제 a[1]을 가리킴
cout << *p << '\n';        // 2
cout << p - a << '\n';     // 1   ← 같은 배열 안 두 포인터의 차이 = 칸 수
```

- 같은 배열 안의 두 포인터를 빼면 **원소 개수 차이**가 나옵니다.
- 배열 범위를 벗어난 칸을 역참조하면 UB입니다.

### 5-3. 배열 이름과 포인터 변수는 같지 않다

| 비교 | 배열 `int a[5]` | 포인터 `int* p = a` |
| --- | --- | --- |
| `sizeof` | 20 (원소 5개 × 4바이트) | 8 (64비트 환경의 주소 크기) |
| `a = p;`, `a++` | **컴파일 오류** (배열 이름은 대입·증가 불가) | `p++` 가능 |
| 함수 매개변수 `int a[]` | 실제로는 `int* a`와 같음 | |

> [!NOTE]
> 배열 이름은 "그 자리에 고정된 이름표"이고, 포인터는 "옮길 수 있는 쪽지"라고 생각하세요. 이름표는 떼어서 다른 데 붙일 수 없지만(`a++` 불가), 쪽지는 다른 번호로 고쳐 쓸 수 있습니다(`p++` 가능). 함수에 배열을 넘기면 주소만 넘어가므로 함수 안에서 `sizeof`로 배열 크기를 구할 수 없고, 그래서 크기 `n`을 따로 넘깁니다.

### 5-4. `*p++`와 `(*p)++` (우선순위)

후위 `++`가 단항 `*`보다 먼저 묶입니다. 괄호가 없으면 **포인터가 움직이고**, 괄호로 `(*p)`를 묶어야 **값이 바뀝니다**.

| 식 | 묶음 | 하는 일 | 식의 값 |
| --- | --- | --- | --- |
| `*p++` | `*(p++)` | **포인터**를 다음 칸으로, 값은 이동 전 칸 | 이동 전 원소 |
| `(*p)++` | | 가리키는 **값**을 1 증가 | 증가 전 값 |
| `*++p` | `*(++p)` | 포인터를 먼저 이동 | 이동 후 원소 |
| `++*p` | `++(*p)` | 값을 먼저 증가 | 증가 후 값 |

> [!NOTE]
> 외우는 요령: **`++`가 `p` 바로 옆에 붙으면 포인터가 움직이고, `*p`에 붙으면 값이 바뀐다.** 앞에 붙으면(전위) 바뀐 뒤의 것을, 뒤에 붙으면(후위) 바뀌기 전의 것을 식의 값으로 씁니다.

> [!QUIZ]
> 다음 출력을 쓰시오.
>
> ```cpp
> int arr[] = {10, 20, 30, 40};
> int* p = arr;
> cout << *p++ << ' ';
> cout << (*p)++ << ' ';
> cout << *++p << ' ';
> cout << ++*p << ' ';
> cout << *(p + 1) << ' ' << p[-1] << ' ' << p - arr << '\n';
> for (int v : arr) cout << v << ' ';
> ```

> [!ANSWER]
> ```text
> 10 20 30 31 40 21 2
> 10 21 31 40
> ```
>
> | 식 | 출력 | p 위치 | 배열 |
> | --- | ---: | ---: | --- |
> | `*p++` | 10 | 1 | 10 20 30 40 |
> | `(*p)++` | 20 | 1 | 10 **21** 30 40 |
> | `*++p` | 30 | 2 | |
> | `++*p` | 31 | 2 | 10 21 **31** 40 |
> | `*(p + 1)`, `p[-1]`, `p - arr` | 40, 21, 2 | 2 | |

> [!QUIZ]
> `int a[5] = {1, 2, 3, 4, 5}; int* p = a;`일 때 출력과 오류를 판정하시오. (64비트 환경)
>
> ```cpp
> cout << sizeof(a) << ' ' << sizeof(p) << ' ' << *(a + 2) << ' '
>      << *(p + 4) << ' ' << (a + 2 == &a[2]) << '\n';
> a = p;      // (가)
> a++;        // (나)
> p++;        // (다)
> ```

> [!ANSWER]
> 출력: `20 8 3 5 1`. (가)와 (나)는 **컴파일 오류**(배열 이름은 대입·증가할 수 없음), (다)는 정상입니다.

### 5-5. 포인터로 배열 훑기

`for`의 인덱스 대신 포인터를 한 칸씩 옮기며 배열을 훑을 수 있습니다.

```cpp
int a[5] = {3, 1, 4, 1, 5};
int sum = 0;
for (int* p = a; p < a + 5; p++) {   // a+5는 마지막 칸 "다음" 위치(끝 표시)
    sum += *p;
}
cout << sum;   // 14
```

2차원 배열도 메모리에 한 줄로 있으므로 `int* p = &m[0][0];`이면 `*(p + i * 열수 + j)`가 `m[i][j]`입니다. `int m[2][3]`에서 `*(p + 4)`는 `m[1][1]`입니다.

```text
m[0][0] m[0][1] m[0][2] m[1][0] m[1][1] m[1][2]
  p+0     p+1     p+2     p+3     p+4     p+5
```

**포인터 배열과 이중 포인터** (Lecture 6 슬라이드 32–34)

```cpp
int a[] = {0, 1, 2};
int b[] = {4, 5, 6};
int* x[2];            // int 포인터 두 개짜리 배열
x[0] = a;  x[1] = b;
std::cout << *(x[1] + 1);      // 5
std::cout << *(*(x + 1) + 1);  // 5 (같은 식)

int m[2][3] = {{0, 1, 2}, {4, 5, 6}};
std::cout << m[1][1] << *(m[1] + 1) << *(*(m + 1) + 1);   // 5 5 5 — 모두 같은 원소
```

포인터도 변수이므로 **포인터를 가리키는 포인터**(`int **y`)를 만들 수 있습니다. `*`의 개수가 화살표를 몇 번 따라가는지입니다.

## 6. C 문자열

C 문자열은 끝에 값이 0인 **널 문자**가 있는 `char` 배열이고, 포인터로 자주 다룹니다.

```cpp
int count_string(const char *s) {     // 방법 1: 하나씩 세기
    int n = 0;
    while (*s) { n++; s++; }          // s가 가리키는 글자가 0이 아닌 동안
    return n;
}
int count_string2(const char *s) {    // 방법 2: 포인터 뺄셈
    const char *ptr = s;
    while (*ptr) ptr++;
    return ptr - s;                   // 같은 배열 안 두 포인터의 차 = 칸 수
}
count_string("RPI");   // 3
```

C 문자열은 `'\0'`(널 문자, 값 0)으로 끝나는 `char` 배열입니다(기초는 04강). `"abc"`는 실제로 `'a' 'b' 'c' '\0'` 네 칸입니다.

```text
char s[] = "abc";
┌───┬───┬───┬────┐
│ a │ b │ c │ \0 │   ← sizeof(s) = 4, strlen(s) = 3
└───┴───┴───┴────┘
```

포인터로 `'\0'`을 만날 때까지 순회할 수 있습니다.

```cpp
const char* s = "abc";
while (*s) cout << *s++;      // '\0'(0)이면 거짓 → 종료. 출력: abc
```

`*s++`는 5절에서 본 대로 "지금 글자를 꺼내고 포인터를 다음 글자로"입니다.

| 함수 | 역할 | 주의 |
| --- | --- | --- |
| `strlen(s)` | `'\0'` 앞까지의 문자 수 | `sizeof`(배열 전체 크기)와 다름 |
| `strcpy(dst, src)` | 복사 | `dst`가 충분히 커야 함 |
| `strcat(dst, src)` | 뒤에 이어 붙이기 | `dst`가 충분히 커야 함 |
| `strcmp(a, b)` | 같으면 0, a가 사전순으로 앞이면 음수, 뒤면 양수 | 대문자(65~)가 소문자(97~)보다 앞 |

> [!TRAP]
> - 문자열은 `==`로 비교하지 않습니다. `char` 배열끼리 `==`는 **주소**를 비교합니다. `strcmp(a, b) == 0`을 쓰세요.
> - 문자 배열에 `name = "Kim";`처럼 대입할 수 없습니다(배열 대입 불가). `strcpy(name, "Kim");`을 씁니다. 빈 문자열은 `strcpy(name, "");` 또는 `name[0] = '\0';`.
> - `cin >> name`은 공백 전까지만 읽습니다. 한 줄 전체는 `cin.getline(name, 크기)`.

> [!QUIZ]
> 다음 출력을 쓰시오.
>
> ```cpp
> char a[20] = "Hello";
> char b[] = "World";
> cout << strlen(a) << ' ' << sizeof(a) << ' ' << sizeof(b) << ' ';
> strcat(a, b);
> cout << a << ' ' << strlen(a) << ' ';
> cout << (strcmp("abc", "abd") < 0) << ' ' << strcmp("abc", "abc") << ' '
>      << (strcmp("b", "a") > 0) << ' ' << (strcmp("Zoo", "apple") < 0) << '\n';
> ```

> [!ANSWER]
> ```text
> 5 20 6 HelloWorld 10 1 0 1 1
> ```
>
> `sizeof(a)`는 선언한 크기 20, `sizeof(b)`는 `"World"` 다섯 글자 + `'\0'` = 6입니다. `"Zoo" < "apple"`인 이유: `'Z'`(90)가 `'a'`(97)보다 작기 때문입니다.

## 7. 힙과 동적 메모리

[![스택의 지역 포인터 변수가 힙에 new로 빌린 블록을 가리키고 주소를 잃은 블록은 돌려줄 수 없는 누수가 되는 그림](/materials/diagrams/cpp-05-stack-heap.svg)](/materials/diagrams/cpp-05-stack-heap.svg)

*그림 5-4 · 스택과 힙 — 누르면 원본 크기로 열린다.*

**sizeof** — 자료형(또는 변수)이 차지하는 바이트 수를 알려 줍니다: `std::cout << sizeof(int);` → 보통 4.

**힙(heap)**은 **실행 중에** 메모리를 빌릴 수 있는 특별한 영역입니다. 지금까지 배열은 선언할 때 크기를 정해야 했지만(`x[10]`), 힙을 쓰면 **실행 중에야 아는 크기**의 배열을 만들 수 있습니다.

**C 방식 (`<stdlib.h>`)** — 다음 학기 C 코드에서도 만납니다.

| 함수 | 하는 일 |
| --- | --- |
| `calloc(n, el_size)` | 원소 n개 × el_size 바이트의 연속 공간 (0으로 채움) |
| `malloc(size)` | size 바이트 공간 |
| `free(p)` | 빌린 공간 반납 (크기는 C가 내부에 기억) |

```cpp
int *arr = (int*)malloc(n * sizeof(int));   // C++에서는 void*를 명시적으로 변환해야 함
free(arr);
```

> [!TRAP]
> C에서는 `void*`가 다른 포인터로 **자동 변환**되지만 C++에서는 **컴파일 오류**입니다. 그래서 `int *p = fun();`(fun이 `void*` 반환)은 C에서는 되고 C++에서는 안 됩니다. C++에서는 아래의 `new`를 씁니다.

### 7-1. 왜 필요한가

지금까지의 변수는 **컴파일할 때 크기가 정해진** 메모리(스택)에 삽니다. 그래서 `int arr[n];`처럼 실행 중에 입력받은 `n`으로 배열 크기를 정하는 것은 표준 C++에서 허용되지 않습니다. 또 지역 변수는 블록이 끝나면 사라집니다.

`new`는 **실행 중에 필요한 만큼** 메모리를 빌려(힙) 그 **주소**를 돌려줍니다. 빌린 메모리는 **직접 `delete`로 돌려줄 때까지** 남아 있습니다.

```text
스택 (자동)                       힙 (직접 관리)
┌────────────┐                  ┌──────────────────┐
│ arr: 주소 ─┼───────────────▶  │ [ ][ ][ ][ ] (n칸)│
└────────────┘                  └──────────────────┘
블록이 끝나면 arr 변수는 사라짐      delete[] 하기 전까지 남아 있음
```

### 7-2. 쓰는 법

```cpp
int* one = new int(42);        // int 하나를 빌리고 42로 초기화
cout << *one;                  // 42
delete one;                    // 돌려줌

int n;
cin >> n;
int* arr = new int[n];         // 실행 중에 크기 결정
arr[0] = 1;                    // 일반 배열처럼 사용
delete[] arr;                  // 배열은 delete[]
arr = nullptr;                 // 댕글링 방지
```

| 할당 | 해제 | 짝이 틀리면 |
| --- | --- | --- |
| `new T` | `delete p` | UB |
| `new T[n]` | `delete[] p` | UB |

> [!NOTE]
> 도서관 책과 같습니다. `new`로 빌린 책은 `delete`로 반납해야 다른 사람이 쓸 수 있습니다. 반납하지 않고 대출증(주소)을 잃어버리면 그 책은 영영 아무도 못 쓰는데, 이것이 **메모리 누수**입니다. 반납한 책의 번호로 다시 책장을 뒤지면 엉뚱한 책이 나오는데, 이것이 **댕글링 포인터**입니다.

### 7-3. 흔한 사고 네 가지

| 문제 | 상황 |
| --- | --- |
| **메모리 누수** | 해제하지 않은 채 주소를 잃음: `p = new int(1); p = new int(2);` |
| **댕글링 포인터** | 해제한 뒤에도 그 주소를 사용: `delete p; *p = 3;` |
| **이중 해제** | 같은 메모리를 두 번 `delete` (UB). `nullptr`에 대한 `delete`는 안전 |
| **스택 변수 해제** | `int x; delete &x;` (UB). `new`로 받은 것만 해제 |

```cpp
int* p = new int(1);
p = new int(2);     // 누수: 1이 든 메모리의 주소를 잃었다

delete p;           // 2가 든 메모리 반납
p = nullptr;        // 반납 후 nullptr → 실수로 다시 써도 바로 드러남
delete p;           // nullptr이므로 아무 일도 안 함(안전)
```

> [!QUIZ]
> 다음 출력을 쓰고, 마지막에 필요한 문장을 쓰시오.
>
> ```cpp
> int n = 4;
> int* d = new int[n];
> for (int i = 0; i < n; i++) d[i] = i * i;
> int* e = d + 1;
> e[1] = 100;
> for (int i = 0; i < n; i++) cout << d[i] << ' ';
> ```

> [!ANSWER]
> `0 1 100 9`. `e`는 `d[1]`을 가리키므로 `e[1]`은 `d[2]`입니다. 마지막에 `delete[] d;`가 필요합니다. `e`를 따로 해제하면 이중 해제가 됩니다.

### 7-4. 이중 포인터

포인터도 변수이므로 주소가 있습니다. **포인터의 주소**를 담는 것이 이중 포인터입니다.

```cpp
int x = 5;
int* p = &x;
int** pp = &p;    // 포인터의 주소
**pp = 9;         // x = 9
```

```text
pp ──▶ [ p ] ──▶ [ x : 9 ]
*pp  = p           (첫 번째 화살표를 따라감)
**pp = x           (두 번째 화살표까지 따라감)
```

`*`의 개수가 **화살표를 몇 번 따라가는지**입니다.

실무에서는 직접 `new[]`/`delete[]`를 쓰는 일을 줄입니다. `vector<int> v(n);`을 쓰면 크기를 실행 중에 정할 수 있고 메모리가 **자동으로** 해제됩니다. 객체 하나를 동적으로 관리할 때는 `unique_ptr<int> p = make_unique<int>(42);`처럼 스마트 포인터를 씁니다(`<memory>`). 이 둘은 소멸할 때 알아서 `delete`해 주므로 누수가 생기지 않습니다. 다만 시험에서는 `new`/`delete`의 짝과 사고 유형이 나오므로 7절을 확실히 알아 두세요.

## 핵심 정리

1. 오버로딩은 매개변수 자료형·개수로 구분하고 컴파일할 때 고른다. 모호하면 컴파일 오류, 반환형만 다르면 오버로딩 아님.
2. `&x`는 주소, `*p`는 가리키는 값. `p = q`는 화살표 이동, `*p = *q`는 값 복사. 포인터 자료형은 가리킬 값과 맞아야 한다.
3. 초기화 안 한 포인터를 역참조하면 segmentation fault 또는 조용한 데이터 손상.
4. 주소를 넘기면 함수가 호출한 쪽 변수를 바꾼다(결과 여러 개 돌려받기). 포인터 자체도 복사되어 전달된다.
5. 배열 이름은 주소가 고정된 포인터. `a[i] == *(a + i)`, `p + 1`은 원소 한 칸.
6. C 문자열은 `'\0'`까지. 포인터 뺄셈으로 길이를 구할 수 있다.
7. 힙: C는 malloc/calloc/free, C++은 new/delete와 new[]/delete[]. 짝을 맞추고 해제 후 nullptr.

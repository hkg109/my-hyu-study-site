## M1. 배열 + `static` 지역변수 추적

### 대표 문제 — 2017/2018 계열

다음 코드의 최종 배열 값을 구하시오.

```cpp
#include <iostream>
using namespace std;

int func(int a[], int k)
{
    static int m = 0;

    a[k] = a[k] + k;

    if (m == 0)
        k = k + 1;

    m = (m + 1) % 2;
    return k;
}

int main()
{
    int a[] = {3, 3, 2, 2, 1};
    int i = 0;

    while (i < 5)
        i = func(a, i);

    for (int j = 0; j < 5; j++)
        cout << a[j] << ", ";
}
```

> [!QUIZ]
> **M1. 배열 + `static` 지역변수 추적 · 확인 1** — 정답 및 추적 과정. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **정답 및 추적 과정**
>
> 최종 배열은 **{3, 5, 6, 8, 9}**입니다. 실제 출력에는 마지막 원소 뒤에도 쉼표와 공백이 붙습니다.
>
> ```text
> 3, 5, 6, 8, 9,
> ```
>
> `m`은 `static`이므로 호출이 끝나도 값이 유지되고 `0 → 1 → 0 → 1 ...`로 반복됩니다.
>
> | 호출 | 시작 k | 시작 m | 변경되는 원소 | k 증가? | 반환 k |
> |---:|---:|---:|---|:---:|---:|
> | 1 | 0 | 0 | `a[0] += 0` → 3 | O | 1 |
> | 2 | 1 | 1 | `a[1] += 1` → 4 | X | 1 |
> | 3 | 1 | 0 | `a[1] += 1` → 5 | O | 2 |
> | 4 | 2 | 1 | `a[2] += 2` → 4 | X | 2 |
> | 5 | 2 | 0 | `a[2] += 2` → 6 | O | 3 |
> | 6 | 3 | 1 | `a[3] += 3` → 5 | X | 3 |
> | 7 | 3 | 0 | `a[3] += 3` → 8 | O | 4 |
> | 8 | 4 | 1 | `a[4] += 4` → 5 | X | 4 |
> | 9 | 4 | 0 | `a[4] += 4` → 9 | O | 5 |

### 변형 — `static`이 아니면?

```cpp
int m = 0;
```

처럼 일반 지역변수라면 함수가 호출될 때마다 `m`이 다시 초기화됩니다. 이 유형에서는 **매 호출마다 같은 분기만 실행되는지** 확인해야 합니다.

### 시험에서 같이 묻는 오류 종류

> [!QUIZ]
> **M1. 배열 + `static` 지역변수 추적 · 확인 2** — 오류 판별 정리. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **오류 판별 정리**
>
> #### 1. 배열 선언 크기보다 초기값이 많음
>
> ```cpp
> int a[3] = {1, 2, 3, 4};
> ```
>
> → **컴파일 오류** (`too many initializers`)
>
> #### 2. 배열 범위를 벗어난 인덱스 접근
>
> ```cpp
> int a[5];
> a[5] = 10;
> ```
>
> 족보에서는 흔히 **runtime error**로 분류합니다.
>
> > 표준 C++에서 더 정확한 표현은 **undefined behavior(정의되지 않은 동작)** 입니다. 반드시 실행 중 오류가 발생한다고 보장되지는 않습니다. 시험에서는 교수님 수업 기준 표현을 우선 확인하세요.
>
> #### 3. `const`로 받은 값을 함수에서 수정
>
> ```cpp
> void add(int a[], const int &k)
> {
>     k = k - 1;   // 오류
> }
> ```
>
> → **컴파일 오류**. `const` 참조를 통해 값을 수정할 수 없습니다.

## M2. 반복문 + 조건문 출력 추적

### 대표 유형 A — 2018 계열

```cpp
#include <iostream>

int main()
{
    int y = 1;

    for (int i = 5; i > 0; i--) {
        if (i % 2 == 1)
            y = y + i;
        else
            y++;

        std::cout << y << std::endl;
    }
}
```

> [!QUIZ]
> **M2. 반복문 + 조건문 출력 추적 · 확인 3** — 정답 보기. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **정답 보기**
>
> ```text
> 6
> 7
> 10
> 11
> 12
> ```
>
> | i | 홀수? | 실행 | y |
> |---:|:---:|---|---:|
> | 5 | O | `y += 5` | 6 |
> | 4 | X | `y++` | 7 |
> | 3 | O | `y += 3` | 10 |
> | 2 | X | `y++` | 11 |
> | 1 | O | `y += 1` | 12 |

### 2020 변형

2020 자료에서는 같은 구조에서 다음처럼 **if/else의 동작을 서로 바꾼 변형**이 출제되었다고 정리되어 있습니다.

```cpp
if (i % 2 == 1)
    y++;
else
    y = y + i;
```

> 숫자와 한 줄만 바꿔서 출제되는 패턴이므로, 답을 암기하지 말고 매 반복마다 `i`, 조건 결과, `y`를 표로 적는 것이 안전합니다.

### 2023 중간고사 1번 — 출력값

> 아래 내용은 **2023 중간고사 PDF의 인쇄된 코드만** 반영했습니다. 손글씨 필기는 사용하지 않았습니다.

```cpp
#include <iostream>

void main()
{
    int y = 0;

    for (int i = 5; i > 0; i--) {
        if (i % 3 == 1)
            y++;
        else
            y += i;

        std::cout << "y = " << y << "\n";
    }
}
```

> ```

## M3. `while`문을 `for`문으로 변환

### 대표 문제

```cpp
int sum = 0;
int j = 0;

while (j <= 10) {
    sum = sum + j;
    j++;
}
```

위 코드를 같은 동작의 `for`문으로 바꾸시오.

> [!QUIZ]
> **M3. `while`문을 `for`문으로 변환 · 확인 5** — 정답 코드. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **정답 코드**
>
> ```cpp
> int sum = 0;
> int j = 0;
>
> for (; j <= 10; j++) {
>     sum = sum + j;
> }
> ```
>
> 최종 `sum`은 `0 + 1 + ... + 10 = 55`이며, 원본처럼 반복문 밖의 `j`도 유지되어 종료 후 11입니다.
>
> ### 변환 규칙
>
> ```cpp
> 초기식;
> while (조건식) {
>     실행문;
>     증감식;
> }
> ```
>
> ↕
>
> ```cpp
> for (초기식; 조건식; 증감식) {
>     실행문;
> }
> ```

### 2020 변형

자료에는 다음과 같은 변형이 언급되어 있습니다.

```cpp
while (j > 0)
    sum = sum + j--;
```

동일한 구조는 다음처럼 바꿀 수 있습니다.

```cpp
for ( ; j > 0; j--)
    sum = sum + j;
```

> `j--`가 **합산 후** 수행된다는 점을 놓치지 마세요.

## M4. 참조 변수 + 값 전달/참조 전달 + 오류 찾기

### 대표 문제

```cpp
#include <iostream>
using namespace std;

void hi(int &x, int y)
{
    x = x + 10;
    y = y - 10;
}

int main()
{
    int x = 2;
    int y = 3;

    int &var1 = x;
    int &var2;
    var2 = y;

    hi(var1, var2);
    cout << x << " " << y;
}
```

> [!QUIZ]
> **M4. 참조 변수 + 값 전달/참조 전달 + 오류 찾기 · 확인 6** — 오류 및 정답 보기. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **오류 및 정답 보기**
>
> ### 오류
>
> ```cpp
> int &var2;
> ```
>
> 참조 변수는 선언과 동시에 반드시 참조할 대상을 지정해야 합니다.
>
> ```cpp
> int &var2 = y;
> ```
>
> ### 수정 후 출력
>
> ```text
> 12 3
> ```
>
> - `x` → `int&`로 전달 → 원본 변경
> - `y` → 값으로 전달 → 함수 내부 복사본만 변경

### 2023 중간고사 2번 — 컴파일 오류 찾기 / 수정 / 출력

> 아래 코드는 **2023 중간고사 PDF의 인쇄된 코드만** 옮긴 것입니다. 코드 위에 적힌 손글씨 수정 내용은 반영하지 않았습니다.

```cpp
#include <iostream>

void fun(int &r, int v)
{
    r = r + 100;
    v = v - 100;
}

void main()
{
    int i = 2;
    int j = 3;
    int &r1 = i;
    int &r2;
    r2 = j;

    fun(i, j);

    std::cout << "i : " << i << std::endl;
    std::cout << "j : " << j << std::endl;
}
```

문제에서 요구하는 것은 다음 네 가지입니다.

1. 컴파일 오류가 발생하는 문장을 찾기
2. 오류를 수정하기
3. 수정된 코드의 출력값 쓰기
4. `int i = 2;`를 `const int i = 2;`로 바꿔도 되는지 설명하기

> [!QUIZ]
> **M4. 참조 변수 + 값 전달/참조 전달 + 오류 찾기 · 확인 7** — 정답 및 해설. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **정답 및 해설**
>
> ### 1) 잘못된 문장
>
> ```cpp
> int &r2;
> ```
>
> 참조 변수는 선언할 때 바로 참조 대상을 지정해야 하므로 컴파일 오류가 발생합니다.
>
> ### 2) 수정
>
> ```cpp
> int &r2 = j;
> ```
>
> 이렇게 수정하면 뒤의 `r2 = j;`는 불필요하지만 문법적으로는 실행 가능합니다.
>
> ### 3) 출력
>
> `fun(i, j)`에서 첫 번째 인수 `i`는 참조로 전달되고 두 번째 인수 `j`는 값으로 전달됩니다.
>
> ```text
> i : 102
> j : 3
> ```
>
> ### 4) `const int i = 2;`로 바꿀 수 있는가?
>
> 불가능합니다. `int &r1 = i;`도 수정 가능한 참조에 상수를 연결하므로 오류입니다. 또한 `fun`의 첫 번째 매개변수는 수정 가능한 참조 `int &r`이므로 `const int`를 전달할 수 없습니다.
>
> ```cpp
> const int i = 2;
> fun(i, j);   // 컴파일 오류
> ```

## M5. 참조와 포인터 개념 문제

### 1) 배열 인덱싱과 포인터 연산

```cpp
arr[i]
```

와

```cpp
*(arr + i)
```

는 같은 원소를 가리킵니다.

### 2) 참조의 주소

```cpp
int n = 3;
int &k = n;
int *p = &n;
```

다음 문장을 판별하시오.

```cpp
p[0] == n
p = &k
```

> [!QUIZ]
> **M5. 참조와 포인터 개념 문제 · 확인 8** — 정답. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **정답**
>
> 둘 다 가능합니다.
>
> - `p[0]`은 `*p`, 즉 `n`
> - `k`는 `n`의 별명(alias)이므로 `&k`는 사실상 `&n`

## M6. 재귀함수 → 반복문 변환

이 유형은 여러 해에 반복되었고, **base case가 조금씩 바뀝니다.** base case를 먼저 확인해야 합니다.

### 유형 A — `f(0) = 5`

```cpp
int f(int x)
{
    if (x <= 0)
        return 5;
    else
        return f(x - 1) + f(x - 1);
}
```

> [!QUIZ]
> **M6. 재귀함수 → 반복문 변환 · 확인 9** — 점화식 / f(4) / 반복문 정답. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **점화식 / f(4) / 반복문 정답**
>
> ```text
> f(x) = 2f(x-1)
> f(0) = 5
> ```
>
> 따라서:
>
> ```text
> f(1) = 10
> f(2) = 20
> f(3) = 40
> f(4) = 80
> ```
>
> 반복문:
>
> ```cpp
> int f(int x)
> {
>     int result = 5;
>
>     for (int i = 0; i < x; i++)
>         result *= 2;
>
>     return result;
> }
> ```

### 유형 B — `f(1) = 5`

2017/일부 2018 자료에는 사실상 다음 구조도 나타납니다.

```cpp
int f(int x)
{
    int i = x - 1;

    if (i <= 0)
        return 5;
    else
        return f(x - 1) + f(x - 1);
}
```

즉 base case가 `x <= 1`입니다.

> [!QUIZ]
> **M6. 재귀함수 → 반복문 변환 · 확인 10** — 정답. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **정답**
>
> ```text
> f(1) = 5
> f(2) = 10
> f(3) = 20
> f(4) = 40
> ```
>
> > 유형 A와 코드가 거의 같아 보여도 base case 하나 때문에 답이 **80 ↔ 40**으로 달라집니다.

### 2020 변형 — base case 반환값이 1

자료에는 다음 점화식 형태가 언급됩니다.

```text
f(n) = 1                      (n <= 0)
       f(n-1) + f(n-1)        (n > 0)
```

> [!QUIZ]

### 2023 중간고사 3번 — 재귀함수 분석 및 반복문 변환

> 아래 내용 역시 **인쇄된 문제만** 사용했습니다. 여백에 적힌 계산 필기는 반영하지 않았습니다.

```cpp
int g(int x)
{
    if (x <= 0)
        return x + 1;
    else
        return g(x - 1) + g(x - 1) + g(x - 1);
}
```

문제는 다음을 요구합니다.

- a) 위 재귀함수와 같은 동작을 하는 반복문 기반 함수 작성
- b) `g(3)`의 반환값 구하기
- c) 조건을 `x <= 0`에서 `x < 0`으로 바꾸면 `g(100)`의 반환값이 무엇인지 구하기

> [!QUIZ]
> **M6. 재귀함수 → 반복문 변환 · 확인 12** — 정답 보기. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **정답 보기**
>
> ### a) 반복문 버전
>
> `x > 0`일 때 `g(x) = 3g(x-1)`이고 `g(0)=1`입니다.
>
> ```cpp
> int g(int x)
> {
>     if (x <= 0)
>         return x + 1;
>
>     int result = 1;
>
>     for (int i = 0; i < x; i++)
>         result *= 3;
>
>     return result;
> }
> ```
>
> ### b) `g(3)`
>
> ```text
> g(0) = 1
> g(1) = 3
> g(2) = 9
> g(3) = 27
> ```
>
> **정답: `27`**
>
> ### c) 조건이 `x < 0`이면
>
> 이 경우 `x = 0`은 `else`로 들어가며,
>
> ```text
> g(0) = g(-1) + g(-1) + g(-1)
>       = 0 + 0 + 0
>       = 0
> ```
>
> 따라서 이후 모든 양의 정수에서도 결과는 0입니다.
>
> **정답: `g(100) = 0`**
>
> 이는 점화식으로 구한 값입니다. 같은 재귀 호출을 세 번씩 반복하므로 실제로 실행해서 확인하기에는 호출 수가 지나치게 많습니다. 원래 조건의 함수도 결과가 `int` 범위를 넘는 입력에서는 정수 오버플로에 주의해야 합니다.

## M8. 단락 평가(Short-circuit evaluation)

2017 자료에서 추가 출제 가능 항목으로 언급된 내용입니다.

| 식의 앞부분 | 연산자 | 뒤 식 실행? |
|---|:---:|:---:|
| `true` | `&&` | O |
| `false` | `&&` | X |
| `true` | `\|\|` | X |
| `false` | `\|\|` | O |

예:

```cpp
int x = 0;
false && (++x);   // x는 그대로 0
true  || (++x);   // x는 그대로 0
```

> [!QUIZ]
> **M8. 단락 평가(Short-circuit evaluation) · 확인 14** — 왜?. 먼저 답을 떠올린 뒤 해설과 비교하세요.

> [!ANSWER]
> **왜?**
>
> - `false && ...`는 앞이 이미 거짓이므로 전체가 무조건 거짓 → 뒤를 확인하지 않음
> - `true || ...`는 앞이 이미 참이므로 전체가 무조건 참 → 뒤를 확인하지 않음
>
> 즉, **결과를 결정하기 위해 뒤 식을 볼 필요가 없으면 뒤 식은 실행되지 않습니다.**

## M9. 에러 유형 총정리

| 코드/상황 | 시험에서 답할 유형 | 이유 |
|---|---|---|
| `int &r;` | Compile error | 참조는 선언 즉시 초기화 필요 |
| `int a[3] = {1,2,3,4};` | Compile error | 초기값 개수가 배열 크기 초과 |
| `const int &k`를 함수 안에서 수정 | Compile error | `const` 수정 불가 |
| `a[5]` 접근 (`int a[5]`) | 족보상 Runtime error | 실제 C++ 기준 undefined behavior |
| 함수 이름 오타 (`something`/`somthing`) | Compile error | 선언되지 않은 함수 호출 |
| 반환값으로 인덱스를 갱신해야 하는데 무시 | 논리 오류 / 무한루프 가능 | 반복 조건의 변수가 변하지 않을 수 있음 |

## Part D. 시험 직전 압축 암기

## 1. 반드시 손으로 풀 수 있어야 하는 것

- [ ] `static` 지역변수는 함수 호출이 끝나도 값이 유지된다.
- [ ] 일반 지역변수는 함수 호출 때마다 다시 초기화된다.
- [ ] `a[i] == *(a + i)`.
- [ ] 참조 변수 `int &r`는 선언 즉시 초기화해야 한다.
- [ ] 값 전달은 원본을 바꾸지 않고, 참조 전달은 원본을 바꿀 수 있다.
- [ ] `const int&`는 읽을 수 있지만 그 참조를 통해 수정할 수 없다.
- [ ] `while` → `for`로 바꿀 때 초기식/조건식/증감식을 하나도 잃지 않는다.
- [ ] 재귀 문제는 **base case를 먼저 적고** 점화식을 찾는다.
- [ ] `&&`, `||`는 short-circuit 때문에 뒤의 증감식이 실행되지 않을 수 있다.
- [ ] 배열 문제는 인덱스를 매 호출/반복마다 표로 추적한다.
